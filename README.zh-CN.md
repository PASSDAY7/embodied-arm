## 0. 三句话速览

1. 这个仓库的长期目标（2027 年投稿 IROS/RA-L）是：**让机械臂在"控制器不够准"的情况下依然能精准跟踪轨迹**，方法是在一个传统控制器上叠加一个强化学习学出来的"修正量"（Residual RL）。
2. 目前处在打基础的阶段：先用最便宜的小环境（**倒立摆 Pendulum**）把"**模仿学习 / 行为克隆**"这条流水线完整跑通 —— 数据采集、训练、监控、断点续训、闭环评估一个不少。
3. 当前这一步（W4 Task 1）的增量是"**动作块行为克隆（Action Chunking BC）**"：让网络**一次预测未来 K 步动作**，从而把推理次数降到 1/K。这对真实机械臂很关键，因为机械臂控制频率高、网络前向慢，"一步一推理"常常来不及。

## 1. 先看懂环境：倒立摆（Pendulum-v1）

一切指标都长在这个环境上，所以先花两分钟理解它。

**画面**：一根木棍（摆）的一端固定在转轴上，另一端自由。你要做的就是给转轴施加**力矩**，
把木棍从下垂状态"甩"上去，然后让它**稳稳立住**（倒立）。

**它给策略的信息（观测 / observation，3 个数字）**：

| 分量 | 含义 | 范围 |
| --- | --- | --- |
| `cos θ` | 摆角余弦（为什么不直接给角度？因为 θ 在 ±π 处会突然跳变，cos/sin 不会） | [-1, 1] |
| `sin θ` | 摆角正弦 | [-1, 1] |
| `θ̇` | 角速度 | [-8, 8] rad/s |

**策略能做的动作（action，1 个数字）**：力矩 `τ`，范围 `[-2.0, 2.0]`。正负号表示往哪边推。

**一个回合（episode）**：固定 **200 步**，每步 `0.05` 秒，所以一个回合 = 10 秒仿真。

**每步的奖励（reward）**：

```
reward = -( θ² + 0.1·θ̇² + 0.001·τ² )        （θ 用弧度，θ̇ 用 rad/s，τ 用 N·m）
```

意思是：**角度越偏、转得越快、力矩越猛，扣分越多**；奖励永远是 ≤ 0 的数，越接近 0 越好。
这条公式决定了后面所有"回报"数字的量级：

| 情形 | 每步奖励 | 200 步总回报 |
| --- | --- | --- |
| 倒立静止（理想最好） | ≈ 0 | ≈ **0** |
| 完全下垂且不动（最糟的"躺平"） | -π² ≈ -9.87 | ≈ **-1974** |
| 下垂同时还在以最大角速度乱转 | -16.27 | ≈ **-3254**（理论最差） |
| **本工程实测**：专家控制器 | -0.88 | ≈ **-175** |
| **本工程实测**：训练好的策略 | -0.78 | ≈ **-156** |

> 所以看到回报 `-156` 不要慌：**这个环境里负数是正常的**，-156 已经接近"立住 10 秒"的水平了。

## 2. 六个必须先知道的名词

| 名词 | 白话解释 | 在本工程里对应什么 |
| --- | --- | --- |
| **状态 state**（符号 `s`） | 此刻"局面"的全部信息 | 倒立摆的 `[cos θ, sin θ, θ̇]`（3 个数） |
| **动作 action**（符号 `a`） | 此刻做出的决定 | 力矩 `τ`（1 个数） |
| **策略 policy**（符号 `π`） | 一张"看到状态 → 输出动作"的映射表，也就是我们要训练的东西 | 一个神经网络（MLP/CNN/GRU），输入 3 维、输出 1 维（或 K 维，见第 6 节） |
| **回合 episode** | 从开局到结束的一整段交互 | 200 步 = 1 个回合 |
| **回报 return** | 一个回合里所有步奖励的**总和**，衡量"这一回合表现好不好" | -156、-175…… 越接近 0 越好 |
| **专家 expert / oracle** | "有正确答案的人"：一个已经会做这件事的控制器 | `src/datasets.py` 里的 `expert_controller`（能量塑形摆起 + PD 平衡，手写公式，不用学习） |

对初学者最容易混的一点：**"策略"就是网络本身**。图上说"策略输出动作"，代码里就是 `model(state) -> action`。

## 3. 什么是行为克隆（Behavior Cloning, BC）

**一句话**：把"专家怎么开车"录下来，然后**当成普通的监督学习**去模仿 —— 输入是状态，标签是专家的动作。

* **传统监督学习**：输入猫的图片 → 标签"猫"；
* **行为克隆**：输入状态 `s_t` → 标签"专家此刻会给出的力矩 `a_t`"。

训练目标就是让网络的输出尽量贴近专家：用**均方误差（MSE）**衡量差距，
`损失 = ((网络输出 - 专家动作)²) 的平均`，然后反向传播、更新网络权重。循环 100 遍（epoch）就学会了。

它属于"**模仿学习**"这个大方向里最简单的一种。之所以先学它，是因为：

* 不需要设计奖励函数（奖励从哪来是 RL 的难点）；
* 训练过程就是监督学习，稳定、好调试、几秒钟一轮；
* 是后面 ACT、Diffusion Policy 等主流机器人策略的共同底座。

**它的天然弱点**（务必记住，第 6 节解释动作块时要用）：
BC 只在"专家走过的状态"上被训练过。一旦策略自己走歪到没见过的状态，它就会输出垃圾动作，
越走越歪 —— 这叫 **误差累积（compounding error）**，也是"闭环（closed-loop）"评估存在的意义。

## 4. 数据是怎么来的

工程里没有现成的"专家数据集"，数据是**现采的**，脚本里一行行跑出来的：

```
expert_controller(state) → τ            # 手写控制器（能量塑形 + PD）
把 (state, τ) 一条条存下来 → 10000 步
```

* 每个回合 200 步，共采 **50 个回合 = 10000 条 (s, a) 样本**；
* 缓存成两个文件（都用 `numpy.savez_compressed` 存，避免每次重新跑仿真）：

| 文件 | 内容 | 谁在用 |
| --- | --- | --- |
| `data/expert_pendulum/expert_pendulum.npz` | 扁平的 `states (10000,3)` + `actions (10000,1)` | 单步 BC |
| `data/expert_pendulum/expert_pendulum_traj.npz` | 上面两个 **加上 `episode_lengths`（每回合多少步）** | 动作块 BC（要靠它才能知道回合边界） |

* 然后按 **80% / 20%** 随机切成训练集（8000 条）和验证集（2000 条）。
  切分用 `numpy.random.default_rng(seed).permutation(N)`，**固定种子 42**。
  这一点很重要：单步 BC 与动作块 BC 用的是**同一批状态、同一个切分**，
  所以两者对比时，"唯一变量"只有标签形式和执行方式，结果才干净可信。

## 5. 一次训练从头到尾发生了什么

```
① 准备数据                ② 训练                     ③ 评估
┌──────────────┐   ┌────────────────────────┐   ┌──────────────────────────┐
│ 加载/采集专家  │   │ 每个 epoch:             │   │ 加载"验证集 MSE 最小"的    │
│ 数据 10000 步  │──▶│  取 64 条一批 → 网络前向 │──▶│ best.pt，放进环境跑 20 个  │
│ 8:2 切分      │   │  → MSE 损失 → 反向传播  │   │ 回合，输出平均回报 & 推理  │
│ DataLoader    │   │  每轮结束在验证集上测评  │   │ 次数（这才是最终指标）     │
└──────────────┘   └────────────────────────┘   └──────────────────────────┘
                            ↓ 全过程写入
                    logs/<实验名>_<时间>/  (TensorBoard 曲线)
                    logs/checkpoints/     (best.pt / last.pt，支持断点续训)
```

**关键的训练设置**（都在 `configs/bc_config.yaml`，改配置即可，不用改代码）：

| 配置项 | 值 | 白话解释 |
| --- | --- | --- |
| `model.name` | `mlp` | 用最简单的全连接网络（3 → 64 → 64 → 输出） |
| `hidden_dim` | 64 | 隐藏层宽度，决定网络"容量" |
| `training.batch_size` | 64 | 每次拿 64 条样本算一次梯度 |
| `training.epochs` | 100 | 把所有训练数据过 100 遍 |
| `training.lr` | 0.001 | 学习率（Adam 优化器），步子大小 |
| `data.train_ratio` | 0.8 | 80% 训练、20% 验证 |
| `augmentation.state_noise_std` | 0.01 | 给状态加一点点噪声，防止死记硬背 |
| `experiment.seed` | 42 | 固定随机种子，保证可复现 |

网络规模：约 **4481 个可训练参数**（K=1）、**4676**（K=4）、**4936**（K=8）。
整个训练在 RTX 2080 Ti 上约 **85 秒**，所以可以放心反复做实验。

> **为什么 validation（验证集）这么重要？**
> 训练集损失一直降，不代表学得好 —— 可能只是把 8000 条数据背下来了（过拟合）。
> 验证集是"没见过的考卷"，用它选出最优权重（best.pt）更靠谱。

## 6. 什么是"动作块"（Action Chunking）—— 本节是重点

### 6.1 为什么需要它？

真实机械臂的控制回路是**固定频率**的：比如 50 Hz，意味着每 20 毫秒必须给出一个新的力矩。
如果每个时刻都跑一次神经网络：

```
读传感器 → 网络前向（5~50ms）→ 输出力矩 → 执行 → 再读传感器 → 再前向 …
```

* 网络一慢，控制就"卡"，跟不上；
* 相邻两次前向收到的输入几乎一样，输出的抖动会直接传到电机上。

**动作块（action chunk）的思路非常朴素**：让网络**一次吐出未来 K 个动作**，然后把这 K 个动作
按顺序播出去，中间**不再推理**。这样推理次数就降到 1/K：

| K | 一个 200 步回合需要推理几次 | 相比单步 BC 省了多少 |
| --- | --- | --- |
| 1（单步 BC） | 200 次 | — |
| 4 | 50 次 | 省 75% |
| 8 | 25 次 | 省 87.5% |

这个思路来自机器人模仿学习里的 ACT（Action Chunking with Transformers）等工作；
本工程实现的是它的**最小可复现版本**（骨干网络还是 MLP，不是 Transformer），
目的是先把"切数据 → 改输出头 → 改闭环调度"这条链路和指标搞清楚。

### 6.2 标签是怎么变的（一张图看懂）

**单步 BC** 的训练样本（每个时刻一条）：

```
s_1 → a_1
s_2 → a_2
s_3 → a_3
```

**动作块 BC（K=4）** 的训练样本（样本数不变，标签"变胖"）：

```
s_1 → [ a_1, a_2, a_3, a_4 ]      ← 一次预测未来 4 步
s_2 → [ a_2, a_3, a_4, a_5 ]
s_3 → [ a_3, a_4, a_5, a_6 ]      ← 相邻样本的标签彼此重叠（滑窗步幅 = 1）
```

网络输出头随之从 `action_dim`（1 维）变成 `K × action_dim`（K=4 → 4 维；K=8 → 8 维）。
实现位置：`src/datasets.py: build_action_chunks()`（切标签）、`src/networks.py: BasePolicy.__init__`（改输出头）。

**两个必须注意的细节**：

1. **窗口绝不跨回合边界**。一个回合只有 200 步，`a_199` 的"未来 4 步"不存在，
   于是尾部**补 0**（零填充），同时用一个 `valid` 掩码标出哪些位置是补的。
   实测零填充占比很小：K=4 时 **0.75%**，K=8 时 **1.75%**。
   *为什么不干脆把尾部样本丢掉？* 因为要保证单步 BC 与动作块 BC 用的是**同样的 10000 个状态**，
   对比才公平。
2. **第一个动作永远是真实专家动作**（`chunk[0] = a_t` 恒成立），零填充只影响块尾。
   而闭环执行时"真正被执行的第一个动作"正是 `chunk[0]`，所以填充不会污染策略的即时反应。

### 6.3 三种执行方式（开环 / 重规划 / 平滑）

```
① chunk —— 开环整块执行（本工程主指标）
   t=0 推理一次 → [a0 a1 a2 a3]  执行这 4 步（这 4 步内"闭着眼"）
   t=4 推理一次 → [a4 a5 a6 a7]  执行这 4 步
   … 200 步共 50 次推理 ✅ 最省算力，❌ 块内不看反馈

② receding —— 每步重规划，只用块首动作
   t=0 推理 → 只执行 a0
   t=1 推理 → 只执行最新规划的第一个动作
   … 200 步共 200 次推理 ✅ 最稳（永远用最新状态）❌ 没省算力

③ ema —— 块间指数移动平均（时间集成）
   每 2 步重规划一次，新旧规划在**时间重叠处**做加权平均后再执行
   ✅ 块与块衔接平滑（减小电机抖动）❌ 会稀释新规划带来的纠正
```

对应配置项（`configs/chunking_bc_config.yaml`）：

| 配置 | 含义 |
| --- | --- |
| `model.chunk_size: 8` | 动作块长度 K（同时决定输出头维度） |
| `inference.execution: "chunk"` | 主评估模式：`chunk` / `ema` |
| `inference.replan_every: 0` | 每多少步重规划一次；`0` = 等于 K（即"每隔 K 步推理一次"） |
| `inference.ema_alpha: 0.5` | EMA 中新规划的权重（`1.0` 等价于不开平滑） |
| `inference.compare_executions: true` | 额外评估 EMA / receding 作为对照，一起写进 TensorBoard |

### 6.4 为什么"开环"走久了会出错（误差累积）

打个比方：**闭着眼睛走 4 步** vs **闭着眼睛走 8 步**。
每走一步都会比预想偏一点，而动作块在块内不接收反馈，所以块越长，偏得越多；
等下次睁眼（重规划）时，已经离目标很远了。这就是 **compounding error（误差累积）**。

本工程的实测把这件事量化了：

| K | 执行方式 | 平均回报 | 标准差 |
| --- | --- | --- | --- |
| 4 | 开环整块 | -155.58 | 66.22 |
| 8 | 开环整块 | **-219.68** | **113.51** |
| 8 | 每步重规划（receding） | **-158.32** | 71.77 |

* K 从 4 增大到 8，开环回报明显变差，**方差也几乎翻倍**（说明有些回合好、有些回合直接崩）；
* 但**同一个 K=8 的网络**，只要改成"每步重规划"，回报立刻回到 -158 —— 说明网络本身学得不差，
  问题出在"执行方式"，不是"模型能力"。

**工程启示**：块长要根据环境变化速度来选。环境变化快（比如接触、摩擦突变）就用小 K，
并在块尾主动提前重规划；反之可以放大 K 来省算力。

### 6.5 一个坑：EMA 必须按"绝对时刻"对齐

K=4、每 2 步重规划、`α=0.5`。假设第一次规划给出动作块 `[0,1,2,3]`，第二次给出 `[10,11,12,13]`：

| 时刻 | 正确做法（按绝对时刻） | 错误做法（按块内下标） |
| --- | --- | --- |
| t=2 | `0.5×10 + 0.5×2 = 6`（两个数都是"对 t=2 的预测"） | `0.5×10 + 0.5×0 = 5`（把 t=0 的旧动作混了进来） |

错误做法相当于**把 4 步前的动作按一半权重混进当前动作**，控制立刻崩掉：
早期版本实测闭环回报掉到 **-981（K=4）/ -1000（K=8）**；改成时间对齐后回到 **-156**，与单步 BC 同级。

> 这个坑已经写成单元测试固化下来：`tests/test_action_chunking.py` 里的
> `test_closed_loop_ema_blends_by_absolute_time`（断言实际执行的动作序列为 `0,1,6,7,16,17,26,27`）。
>
> 另外注意：只有当 `replan_every < K`（相邻两次规划在时间上**有重叠**）时，EMA 才会起作用；
> 如果每 K 步才重规划一次（默认），块之间没有重叠，EMA 与开环执行**逐位相同**。

## 7. 评价指标逐条解读 —— 本节是重点

日志里会出现四类数字，含义完全不同，千万别混：

### 7.1 `train_mse` / `val_mse`：训练指标（"模仿得像不像"）

```
MSE = 预测动作与专家动作之差的平方，在所有样本、所有动作维度上取平均
```

| 数字 | 含义 |
| --- | --- |
| `0.092820`（单步 BC 最优） | 平均平方误差 0.093；开平方 ≈ **0.30 N·m** —— 平均每次比专家差了 0.3 的力矩（动作范围 ±2） |
| `0.196309`（K=4） | 平均差了约 **0.44 N·m** |
| `0.216154`（K=8） | 平均差了约 **0.47 N·m** |

三个必须知道的读法：

1. **它是"模仿精度"，不是"控制水平"**。MSE 小说明学得像专家，但学得像 ≠ 任务完成得好。
2. **不同 K 之间的 MSE 不能直接比大小**。K=8 的标签里包含"8 步之后该做什么"，
   那部分本来就难预测（专家自己 8 步后的动作对当前状态几乎是不可知的），所以数值天然更大。
   它只能和**自己**的曲线比：是否收敛、验证集是否开始回升（过拟合）。
3. **不要只看最后一个 epoch**。脚本保存的是验证集 MSE 最小的那份权重（`best.pt`，本例是第 86/99/98 个 epoch），
   最后用它做闭环评估。

### 7.2 闭环回报 `mean_return ± std`：**真正的成绩单**

```
把训练好的策略放进环境，自己控制 20 个回合（同一种子序列），
每回合记录总回报，最后给出 平均 / 标准差 / 最好 / 最差
```

例：`平均回报: -155.58 ± 66.22 (min -354.02, max -114.95)`

| 数字 | 怎么读 |
| --- | --- |
| `-155.58` | 平均每回合扣 155.58 分；**越接近 0 越好**（0 是理论上限，见第 1 节的标尺） |
| `± 66.22` | 20 个回合的波动（标准差）。有的回合只是"摆起来"（-354），有的回合直接"立住 10 秒"（-115） |
| `min / max` | 最差 / 最好的一回合。`max ≈ -115` 说明**它确实学会了倒立**（-115 ≈ 立住整回合的分数） |

**比较两条结果时看什么？** 看均值差是否**远小于**标准差：
例如 -155.58 vs -156.95，差 1.4，而标准差是 66~69 —— 这种差异属于随机波动，**应当判定为"两者一样好"**。
反过来，-219.68 vs -155.58 差 64，接近一个标准差，就属于"确实变差了"。

### 7.3 每回合前向次数 `forward_per_episode`：工程指标（"跑得动吗"）

```
单步 BC      : 200 次/回合   ← 每步都要推理
动作块 K=4   : 50 次/回合
动作块 K=8   : 25 次/回合
receding（K=8）: 200 次/回合  ← 每步重规划，省不了
```

这就是动作块存在的**唯一理由**：在真实机械臂上，推理次数 = 延迟 = 能不能跟上控制频率。
如果单次前向要 20 ms，单步 BC 在 50 Hz 控制下直接超时；K=4 就变成每 80 ms 推理一次，轻松达标。

> 注意：Pendulum 里"环境步进"本身极快，所以推理次数不影响回报数值；在真机上它决定的是**帧率/成功率**。

### 7.4 为什么这些指标会"互相矛盾"？

| 现象 | 解释 |
| --- | --- |
| val MSE 变小了，闭环回报却没变好 | MSE 衡量"像不像专家"，闭环回报衡量"任务完成度"；而且专家本身不是最优（见 7.5） |
| K=8 的 val MSE 比 K=4 大，但 receding 执行回报一样好 | MSE 里的"远期动作"本来就难预测，而 receding 只用块首动作，几乎不受远期误差影响 |
| 参数更多了（4676 vs 4481），回报却没提升 | 任务太简单，瓶颈不在模型容量，而在**执行方式**与数据质量 |

### 7.5 为什么"学出来的策略"反而比专家分数高？

专家是自己写的控制器（**bang-bang 能量塑形 + PD**），为了让摆尽快摆起来，它的力矩经常在 ±2 之间猛跳，
而奖励里有 `0.001·τ²` 惩罚抖动；网络用 MSE 学出来的是"平均行为"，动作**更平滑**，
于是总扣分更少：专家 -175.00，学到的策略 -156.95。

> 顺便记住这个参照系：`python experiments/eval_expert.py` 可以一键复现专家基线
> （20 回合、seed 42 起的同一种子序列），输出 `mean -175.00 std 83.72`。
> 它代表"数据来源的水平"，也叫 **oracle（先知）上界**，是判断模仿是否成功的标尺。

## 8. 实验结果总表（怎么读这张表）

20 个回合、同一批环境初始状态（种子 42~61），所以每一行都可以直接横向对比：

| 方法 | K | 执行方式 | 每回合推理次数 | 平均回报 | 标准差 | 结论 |
| --- | --- | --- | --- | --- | --- | --- |
| 单步 BC（baseline） | 1 | 每步推理 | 200 | -156.95 | 68.99 | 参照组 |
| 动作块 BC | 4 | 开环整块 | **50** | **-155.58** | 66.22 | ✅ **省 4 倍算力，成绩不变** |
| 动作块 BC | 4 | 块间 EMA | 100 | -155.94 | 66.64 | 与开环同级 |
| 动作块 BC | 4 | 每步重规划 | 200 | -158.06 | 71.42 | 与开环同级 |
| 动作块 BC | 8 | 开环整块 | **25** | -219.68 | 113.51 | ⚠️ 块太长，误差累积 |
| 动作块 BC | 8 | 块间 EMA | 50 | -363.12 | 87.90 | ❌ 平滑稀释了纠正动作 |
| 动作块 BC | 8 | 每步重规划 | 200 | -158.32 | 71.77 | ✅ 换执行方式就恢复了 |
| 专家控制器（oracle） | — | 每步 | — | -175.00 | 83.72 | 数据来源的水平 |

**三句话结论**：

1. **K=4 是甜点**：推理次数降到 1/4（50 次），回报与单步 BC 完全相同（差异 1.4 ≪ 标准差 67）。
2. **K=8 开环会掉分**，但同一个网络改成每步重规划就恢复 —— 掉分的原因在"开环执行太久"，不在网络。
3. **EMA 会"拖后腿"**：K=4 时影响很小，K=8 时明显变差，因为它把新规划的纠偏动作打了对折。
   它更适合用在"动作抖动导致电机发热/磨损"的场景，而不是用来提升回报。

想看训练曲线：`tensorboard --logdir logs`，然后浏览器打开它给出的地址，
可以对比 `train/loss`、`val/mse`、以及各执行模式的 `eval/*` 曲线。

### 8.1 补充实验：扩散策略 vs 确定性回归（W4 Task 2）

Task 1 的策略是"一次前向直接把动作块算出来"（回归）。Task 2 换成了**扩散**：
网络不再直接输出动作，而是学"噪声长什么样"，推理时从一团随机噪声出发，用 `N = 16` 步把它
"擦"成一条动作块。这么做的**唯一理由**是：当同一个状态有两个都对的答案时（比如摆几乎停住，
往左推或往右推都能摆起来），回归只能吐出两者的**平均值**（没往左也没往右 = 谁也摆不起来的动作），
而扩散可以"抽签"选一个真正可行的方向。

| 对比项 | 确定性 MLP（回归均值） | 扩散策略（采样分布） |
| --- | --- | --- |
| 闭环回报（20 回合） | **-181.72 ± 85.99** | -331.83 ± 173.47 |
| 每回合网络前向次数 | **25** | 400（25 次规划 × 16 步去噪） |
| 单次规划耗时 | **0.186 ms** | 24.72 ms（慢 132.8 倍） |
| 参数量 | 18,056 | 358,152 |
| 玩具双峰任务命中率 | 0.0%（输出恰好是两峰中间的 0） | **98.5%**（两侧各采到约一半） |
| 没见过的新歧义状态命中率 | 62.5% | **71.7%** |
| 去噪步数 N = 4 / 10 / 16 / 32 的回报 | — | -494.8 / -325.5 / **-315.2** / -428.7 |

**三句话结论**：

1. **机理上扩散确实更强**：在"状态完全看不出该往哪边推"的玩具任务里，回归的输出严格是 0
   （两个模态都不是），而扩散有 98.5% 的采样落在真正的两个动作上 —— 这是"扩散能表达多峰分布"
   的干净证据（每个状态的 |a| 与解析值 |μ(s)| 逐点吻合）。
2. **但在倒立摆里它没赢**：扩散把没见过的歧义状态命中率从 62.5% 提到 71.7%，代价是慢 132.8 倍，
   并且每次重新规划都可能换一个"抽签结果"（块间方向翻转率 49.2%），闭环回报反而少 150 分。
   原因：摆起过程里"歧义瞬间"只占 0.95% 的状态，其余状态足够让回归器判断方向。
3. **数据更少时扩散更吃亏**（只用 16% 数据：扩散 -882.7 vs 回归 -204.0）：扩散必须先"把两个峰
   学清楚"，数据不够时它输出的分布会变钝（探针平均 |a| 从 1.69 掉到 0.75），比回归更早失效。

一句话记住：**扩散买的是"分布"，不是"分数"；只有当"看不出该选哪个"真正决定成败时，这笔交易才划算。**
详细数据、探针与消融见 `docs/w4_task2_diffusion_policy.md`；
**完全没接触过扩散模型的话，建议先看零基础讲解版
[`docs/w4_task2_diffusion_README.md`](docs/w4_task2_diffusion_README.md)**
（背景动机 → 逐步推导的原理与公式 → 6 组实验结论 → 术语表 + FAQ）。

## 11. 常见疑问（FAQ）

**Q1：K 越大越好吗？**
不是。K 大 = 推理次数少 = 省算力，但块内开环时间变长 → 误差累积。本工程中 K=4 与单步 BC 同分，
K=8 开环明显掉分。合理做法是"环境多快变，块就多长"，或加"提前重规划"的触发条件。

**Q2：为什么 K=1 也是动作块？**
K=1 时输出头维度就是 `1 × action_dim`，退化成普通单步 BC，与 W2/W3 的旧代码**数值逐位一致**，
这是刻意保留的向后兼容（有单测守着）。也就是说"单步 BC"只是"K=1 的动作块 BC"的特例。

**Q3：为什么不直接在机械臂上做？**
按路线图，Isaac Lab + 自研任务要到 W10 才开始。现在用 Pendulum 的原因是：**一次实验 90 秒**，
可以把"切数据、改输出头、改闭环调度、算指标"这条链路的坑先踩完，等到真机上就只剩"域随机化、时延、标定"这些真问题。

**Q4：闭环（closed-loop）和开环（open-loop）到底差在哪？**
* 闭环：策略的动作会**改变**它下一步看到的状态，环环相扣，误差可能被纠正也可能被放大 → 衡量真实水平；
* 开环：一段时间内按计划执行、不看反馈（例如"块内不重规划"），省算力但会漂。
评估里"闭环回报"永远是金标准；`MSE` 只是训练过程中的辅助观察量。

**Q5：为什么要跑 20 个回合、还要报标准差？**
单回合随机性很大（初始状态不同）。20 个回合的**均值**才是稳定估计，**标准差**告诉你这个估计有多不稳。
比较两个方法时，均值差必须显著大于标准差才能说"真的有区别"。

**Q6：`-175` 这样的回报为什么是负数？**
因为这个环境的奖励公式 `-(θ² + 0.1θ̇² + 0.001τ²)` 永远 ≤ 0，它是"扣分制"：
扣得越少越好，0 分是理想极限。完全下垂不动大约 -1974，立住一整回合约 -115。

**Q7：日志里 `推理开销` 那一行有什么用？**
它对应真实机器人上最贵的东西 —— **延迟**。算法论文里常常只比回报，但真机部署时"能不能在控制周期内出动作"是硬约束，
所以本工程把"每回合前向次数"和回报一起报，避免"赢了指标、丢了可用性"。

**Q8：这些代码以后还能用吗？**
能。`src/engine.py`（训练引擎）和 `src/datasets.py` 的数据口径是被两类实验共用的，
以后换成机械臂任务、换成 PPO/SAC（W6-W9）时，日志、检查点、续训、评估上报这套脚手架可以直接搬过去。

**Q9：扩散策略分数更低，为什么还值得做（Task 2）？**
因为它买的东西不是"分数"。回归模型在"同一状态有两个都对的答案"时只能输出两者的平均，
那个平均动作往往两个都不是（在玩具双峰任务里，回归的输出精确等于 0，而扩散 98.5% 的采样落在
真正的两个动作上）。本工程在倒立摆上实测扩散没赢（-331.8 vs -181.7，还慢 132.8 倍），
原因是那里的"歧义瞬间"只占 0.95% 的状态；这类结论恰恰只有量化过才敢下。
详见 `docs/w4_task2_diffusion_policy.md`。

## 12. 术语中英对照

| 中文 | 英文 | 一句话 |
| --- | --- | --- |
| 模仿学习 | imitation learning | 从专家示范里学策略（而不是靠自己试错） |
| 扩散模型 / 去噪 | diffusion model / denoising | 学会"噪声长什么样"，就能从噪声反推出数据 |
| 前向加噪 | forward diffusion (`q_sample`) | 把真实动作一步步加噪，直到变成纯噪声 |
| 反向采样 | reverse sampling | 从纯噪声出发，用网络预测的噪声逐步"擦"回动作 |
| 时间步 | timestep (`t`) | "现在加噪到第几步"，扩散网络的第二个输入 |
| 噪声预测网络 | noise-prediction net (`ε_θ`) | 本工程里就是那个 FiLM MLP |
| 调度表 | noise schedule (`β_t`, `ᾱ_t`) | 每一步加多少噪声（cosine / linear） |
| 去噪步数 | sampling steps (`N`) | 推理擦几步；越少越快、越粗 |
| DDPM / DDIM | DDPM / DDIM | 随机采样 / 可跨步确定性采样（本工程默认 DDIM） |
| 条件分布 | conditional distribution `p(a\|s)` | 同一状态下动作的分布；MSE 只学它的均值 |
| 多峰 / 双峰 | multimodal / bimodal | 分布有多个峰 = 多个都合理的动作 |
| 条件均值 | conditional mean `E[a\|s]` | 回归模型的输出；多峰时可能是"谁也摆不起来"的动作 |
| 行为克隆 | behavior cloning (BC) | 把 (状态, 专家动作) 当监督学习样本去回归 |
| 策略 | policy | 状态 → 动作 的映射（本工程里就是一个网络） |
| 状态 / 观测 | state / observation | 环境给的信息（这里是 3 个数） |
| 动作 | action | 策略的输出（这里是力矩 τ） |
| 回合 | episode | 一次完整的交互（这里 200 步） |
| 回报 | return | 一个回合的累计奖励（越接近 0 越好） |
| 开环 / 闭环 | open-loop / closed-loop | 执行时是否使用最新反馈 |
| 误差累积 | compounding error | 策略走偏后越错越多，BC 的典型病 |
| 动作块 | action chunk | 一次预测未来 K 步动作 |
| 重规划 | replanning | 用最新状态重新推理出新的动作块 |
| 退避式执行 | receding horizon | 每步都重规划，但只执行计划的第一步 |
| 时间集成 / EMA | temporal ensembling | 把多个规划在时间重叠处加权平均，使动作更平滑 |
| 零填充 | zero padding | 轨迹末尾凑不满 K 步时补 0 |
| 专家 / 先知 | expert / oracle | 提供示范的控制器 |
| 均方误差 | mean squared error (MSE) | 训练时用的损失；也可作"模仿精度"的度量 |
| 过拟合 | overfitting | 训练集很好、验证集变差 |
| 残差强化学习 | residual RL | 在传统控制器上叠加 RL 学出的修正量（本课题最终形态） |
