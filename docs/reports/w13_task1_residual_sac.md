## §1 任务与交付物

### 1.1 任务要求（W13 Day 4 + W14 Day 5）

1. **双层控制律**：底层 `τ_base = Ĝ(q) + Kp·e_q + Kd·ė_q`（标称重力前馈 + 线性 PD）；
   上层 SAC 连续高斯策略输出残差 `Δτ ∈ [−15, 15] N·m`；执行 `τ_exec = clip(τ_base + Δτ, ±τ_lim)`；
2. **训练**：64 环境并行 + GPU Replay Buffer，观测用 W12 的 105 维时序向量，奖励复用 W12 的复合奖励
   （其中 jerk 项按任务书要求改成惩罚 `Δτ_t − Δτ_{t−1}`）；

## §2 架构设计（Day 4）

### 2.1 控制律：两层为什么这么分

```text
                    q_d, q̇_d ─┬─> 底层：τ_base = Ĝ(q) + Kp(q_d−q) + Kd(q̇_d−q̇)      ← 标称模型 + M 加权 PD
                              │                     （Kp=ωn²M̂(q0)、Kd=2ζωnM̂(q0)，ωn=30、ζ=1）
                              └─> 上层：SAC(105 维时序观测) → Δτ ∈ ±1.5 N·m（逐关节按刚度归一化）
                                                     │
     τ_exec = clip(τ_base + Δτ, ±τ_lim) ─────────────┘ → Isaac Lab（W11 注入的失配就在这一步上）
```

| 设计点 | 选择 | 理由 |
| --- | --- | --- |
| 基座是否可学 | **否**（固定不变） | 兜底 + A/B 的另一半：任何收益都能归因到 `Δτ`；也避免"策略把基座学坏"这种不可解释的失败 |
| 基座前馈来源 | 标称模型（注入**前**读到的质量/质心） | 控制器不知道负载 ⇒ 前馈本身带模型误差，这正是残差要补的东西（W12 §2.6 的同一口径） |
| 执行限幅 | **显式** `clip(τ_base+Δτ, ±τ_lim)` | 不 clip 的话"算出来的力矩"≠"能给的力矩"，饱和率会被隐藏（W12 §3.3 踩过） |
| PD 符号 | `τ = Kp(q_d−q) + Kd(q̇_d−q̇)`（stabilizing） | 任务书字面写法 `Kp·e_q`（`e_q=q−q_d`）是**正反馈**，W12 §3.1/§4.4 已实测复现（1.802 rad / 57.47 cm / 99% 饱和）；`--pd_sign literal` 可复现 |
| 残差动作缩放 | `Δτ_j = a_norm_j · min(res_limit, deflection·Kp_j)`，`res_limit=1.5`、`deflection=0.2 rad` | **见 §6.1**：tanh 动作空间对各关节"等幅"，而同一个 1 N·m 在 j1 偏 1.8 mrad、在 j7 偏 0.38 rad（差 200 倍） |

### 2.2 上层策略：W9 的 SAC，一行没重写

`src/sac.py` 全套直接复用：`SquashedGaussianActor`（状态相关 `log σ` + tanh 压缩 + 重参数化）、
`ContinuousCritic`（Double-Q）、`SACAgent.update_batch`（Critic → Actor → α → Polyak 三步）、
`build_sac_agent` / `build_sac_optimizers`、`RunningMeanStd`。W13 只补了两件 W9 没有的东西：

1. `GpuReplayBuffer`：W9 的 `ReplayBuffer` 是 host numpy + 单条 `add()`，64 路并行每步要 64 次 host 往返；
   这里换成"整块环形写入（一次 `index_copy_`）+ `torch.randint` 采样"的显存版，
   **字段名 / FIFO 覆盖 / `done` 只含 terminated / `sample()·stats()` 的键全部逐条对齐**
   （`--buffer host` 可切回 W9 原版做对照，两条路径都跑过）。
2. `ResidualReward` / `ResidualPolicy` / `PolicyObsRing`：残差口径的奖励、执行层、观测时序（见 §2.4）。

### 2.3 奖励：任务书四项 + 两项工程补充（**默认参数与任务书的差异写在明处**）

```text
r_t = −10‖e_q‖² − 0.1‖ė_q‖² − 0.001‖τ_exec‖² − 0.01‖Δτ_t − Δτ_{t−1}‖²      ← 任务书四项
        − w_mag‖Δτ_t‖²  − w_ee‖p(q)−p(q_d)‖²                                  ← 本脚本补充（w_mag=0.05、w_ee 见下）
```

| 项 | 默认 | 为什么 |
| --- | --- | --- |
| jerk 项的量 | `Δτ` 差分（**任务书口径**） | 任务书明确写 `Δτ_t − Δτ_{t−1}`；物理上也对：`τ_base` 的抖动来自参考轨迹 `q̈_d`，不该由策略负责。W12 的口径（`τ_exec` 差分）保留为 `--jerk_on exec` |
| `w_mag‖Δτ‖²` | **0.05** | **见 §6.2**：残差结构里 `‖τ_exec‖²` 项会奖励"抵消基座力矩"，w_mag=0 时 `|Δτ|` 漂到 3.5 N·m、末端误差 1.33→2.6 cm。`--w_mag 0` 回到任务书四项（对照臂已跑） |
| `w_ee` | 0（默认）；**臂 A 用 20000、★主结果用 50000** | **见 §6.4**：关节空间奖励 ≠ 末端验收指标。把验收指标本身写进奖励后，末端才真正降下来；`w_ee=0` 的对照臂单独落盘可比 |

### 2.4 RL 时序契约：比 W12 的 `step()` 多走半步（这一条是正确性问题，不是风格问题）

W12 的 `step()` 在"写力矩之前"压入并返回观测 ⇒ 它返回的是**本步所作用的状态**的观测。
对读 `tracking_error(t)` 的控制器没问题（控制器拿的是当前测量值），但对 RL：

* 若直接用 `env.step()` 返回的 obs 当 `next_obs`，则 `(O_t, a_t, r_t, O_{t+1})` 里的 `O_{t+1}`
  其实是"上一动作的结果"，与 `r_t`（本动作的结果）**不对应**——Bellman 目标会被系统性污染；
* W13 因此自带 `PolicyObsRing`：**复用 W12 的 `ObservationBuilder`**（同一个类、同一布局、同样 warm-up 策略），
  只把 push 时机改成"选动作前压当前帧 / 物理步后再压一帧"，于是
  `O_t = obs(x_t)`、`a_t`、`r_t = r(x_{t+1}, a_t)`、`O_{t+1} = obs(x_{t+1})` 严格成四元组；
* **自检**：环给出的 obs 与 `env.step()` 返回的那一份**逐位相同**（实测 `max|Δ| = 0.0e+00`，训练每步核对）。

| UTD | `--gradient_steps 2` | 更新只占单步墙钟的一小部分（25 ms 物理 / 步 vs ~30 ms / 次更新）⇒ 多算一遍梯度很划算 |
| 回放池 | GPU、容量 `--buffer_size 300000` | 臂 A（300k 步）刚好不覆盖；**★主结果 450k 步 ⇒ 后半程开始环形覆盖**（`fill_ratio=1.0`、`total_added=450048` 都落盘，便于判断） |
| 热身 | `--warmup_steps 20000` 环境步、`--warmup_res_scale 1.0` N·m | 先让 Critic 看到"基座自己怎么工作"的分布；W9 那种"整个动作空间均匀随机"在残差结构里 = 乱甩 |
| 观测归一化 | 开（`RunningMeanStd`） | 105 维里 `e_q~1e-2 rad`、`q̇_d~1 rad/s`、`τ~1e1 N·m`，量纲差 3 个数量级；buffer 存归一化后的观测（W9 约定），评估时冻结统计量 |
| 温度 α | **固定** 0.02（`--target_entropy fixed`） | 见 §6.3：自适应温度在这个任务里**反向**——α 从 0.05 一路涨到 0.10，探索噪声把确定性残差顶到 3.1 N·m、末端误差 1.33→2.6 cm |
| `log σ` 初值/下界 | 臂 A **−5 / −5**（σ 钉在下界）；**★主结果 −0.5 / −5**；diag4 / 臂 B −0.5 | 两档都跑过：`log_std_init=-5`（σ=0.0067）⇒ 退化成"确定性策略梯度 + 熵正则"，与评估口径（`tanh(μ)`）一致；`-0.5`（σ=0.61）⇒ 采样覆盖大半个 ±1.5 N·m 区间。★主结果最终 `mean_std = 0.352`（**并未钉在下界**）、tanh 饱和 22.6%。**两档都没能单独解决 §6.4 的对齐问题**——真正起作用的是 `w_ee` |
| Critic 热身 | `--actor_delay_updates 1000` | 前 1000 次更新把 Actor 的 Adam lr 压到 0（只改 `param_group["lr"]`，不动 `src/sac.py`），避免 Actor 在 Q 还没学到价值尺度时就乱跑 |
| 评估 | 每 25k 环境步一次**确定性**（`tanh(μ)`）闭环评估 | 与 baseline 走同一套累加代码；env 本身无额外随机性（DR/轨迹/初值全固定）⇒ 同一策略的评估完全可复现 |

## §6 排错记录（5 个真实坑，都留下了可复现的开关与实测数据）

### 6.1 坑①：残差动作空间不按关节刚度归一化 ⇒ 探索在 j7 上直接是破坏性的

Franka 的 M 加权增益 `Kp = ωn²·M̂(q0)` 跨两个数量级：
`Kp = [568, 2052, 1153, 779, 24.2, 31.3, **2.60**] N·m/rad`（W12 §3.2 的同一组数）。
同一个 1 N·m 的残差在 j1 只造成 1.8 mrad 静态偏转，在 j7 造成 **0.38 rad** —— 差 200 倍。
而 tanh 动作空间的探索是"各关节等幅"的：`σ≈0.22`、`res_limit=5` ⇒ j7 的探索力矩可达 **1.1 N·m ≈ 0.42 rad**，
**比该关节的基线误差（0.17 rad）还大两倍** ⇒ 策略在训练中一直在把 j7 推来推去，Critic 学到的 Q 也被这层噪声主导。

**修法**：`Δτ_j = a_norm_j · min(res_limit, deflection·Kp_j)`（`--res_scale_mode kp`，`--res_deflection_rad 0.2`）
⇒ "满量程 = 各关节相同的静态偏转"，与"关节误差各向同性"的奖励对齐；实测 `scale = [1.5, 1.5, 1.5, 1.5, 1.5, 1.5, 0.52] N·m`。
`--res_scale_mode uniform --res_limit 15` 可回到任务书字面配置。

### 6.2 坑②（**最重要**）：任务书奖励在双层结构里的激励漏洞 —— `‖τ_exec‖²` 项奖励"抵消基座"

把任务书四项在**残差结构**下算一遍（用 W12 量到的基线分项，单步代价，正数）：

| 项 | 基线（零残差） | 占比 |
| --- | --- | --- |
| `w_p‖e_q‖²` | 0.412 | 17% |
| `w_v‖ė_q‖²` | 0.116 | 5% |
| **`w_τ‖τ_exec‖²`** | **1.945** | **79%** |
| `w_j‖Δτ_t−Δτ_{t−1}‖²` | ≈0（Δτ≡0） | 0% |
| 合计 | 2.473 | 100% |

W12 里这项只占 9%（因为那一周 jerk 项占 89%）；到双层结构里 jerk 项被"归零"后，
**`‖τ_exec‖²` 成了主导项**，而它在残差结构里有一个**反向激励**：降低 `‖τ_base + Δτ‖` 最省力的办法是
`Δτ ≈ −τ_base`（**把基座"关掉"**——让 PD/前馈的力矩被残差抵消，机械臂靠重力与扰动自由运动）。
位置项只有 0.41 而 τ 项 1.95 ⇒ 压不住。

**实测（`--w_mag 0`）**：`|Δτ|` 从 0.002 → 0.6 → 2.9 → **3.5 N·m** 单调漂移，
关节 RMSE 0.052 → 0.09 rad、末端 1.33 → **2.6 cm**、W12 口径总代价 22.2 → 反而更差。
**修法**：`--w_mag 0.05`（`w_mag‖Δτ‖²`，任务书四项之外的残差幅值正则）⇒ `|Δτ|` 被按住到 0.85 N·m，
奖励从 −2.4765 降到 −2.1745/步（↓12%）。这条不是"调参"，是**堵一个真实的激励漏洞**：
任务书的三四项（`τ` 幅值 + jerk）默认"策略就是全部力矩"，搬到"策略只出一部分力矩"的结构里必须重新定标。

### 6.3 坑③：自适应温度在这个任务里是**反向**的（但不是根因）

`--target_entropy -1`（自适应 α）时，α 从 0.05 一路涨到 **0.10**（30 万步），
它带来的探索噪声把**确定性**残差从 0.002 顶到 3.1 N·m，末端误差同步 1.33 → 2.6 cm（与 α 同相位上涨）。
**修法**：默认 `--target_entropy fixed` + `--alpha_init 0.02`（SAC 退化成"确定性策略梯度 + 很小的熵正则"）。
**但要诚实**：把它固定之后漂移**仍然存在**（`|Δτ|` 到 3.5 N·m，见 6.2），
说明 α 只是"放大器"，根因是 6.2 的奖励漏洞 + 6.1 的动作空间尺度。

### 6.4 坑④（**结论性**）：关节空间奖励 ≠ 末端验收指标

把 `w_mag=0.05` 那一臂（30 万步，`docs/results/w13_residual_sac_spec_reward.json`）逐关节拆开看：

| 关节 | 基线 `pd_ff_dr` | 残差 SAC | Δ | 该关节对末端位置的杠杆 |
| --- | --- | --- | --- | --- |
| j1 | 0.0370 | **0.0314** | −15% | 长（~0.6 m） |
| j2 | 0.0061 | 0.0079 | +30% | 中 |
| j3 | 0.0228 | **0.0201** | −12% | 长（~0.6 m） |
| j4 | 0.0097 | 0.0161 | +66% | 中 |
| j5 | 0.0432 | 0.0680 | +57% | 中（~0.4 m） |
| j6 | 0.0739 | 0.0923 | +25% | 中（~0.25 m） |
| **j7** | **0.1703** | **0.1404** | **−18%** | **≈0**（关节轴沿法兰 z，手部原点在轴上 ⇒ 纯自转不移动原点） |

于是出现了"奖励变好、验收指标不变"的典型现象：

* 奖励分项：`pos` 0.412→0.359（↓13%）、`vel` 0.116→0.044（**↓62%**，摩擦补偿学出来了）、`tau` 1.945→1.538（↓21%）；
* 但**关节 RMSE 均值**（0.0519→0.0537）与**末端 RMSE**（1.3259→1.3279 cm）**持平**。

原因：奖励是**误差平方和**，j7 独占 0.170² = 0.029 rad²（占七关节平方和的 ~57%），
策略把最大的一块（j7）压小了 18%（最好的一次评估里压到 0.0932 rad，↓45%），
而这**几乎不改变末端位置**；同时 j4/j5/j6（杠杆大）被"提高总力矩/降低 τ 代价"的激励推差了一点。
**修法（主实验采用）**：`--w_ee 20000`，把验收指标本身（`‖p(q)−p(q_d)‖²`）写进奖励
（基线处 ≈3.5/步，与 τ 项同量级）。`w_ee=0` 的对照臂单独落盘，便于"有/无末端项"直接对比。

### 6.6 坑⑤：W12 的 `step()` 返回的 obs 不能直接当 RL 的 `next_obs`

见 §2.4：那份 obs 是"本步所作用的状态"的观测（在写力矩**之前**压入并返回），
直接当 `next_obs` 会让 `(O_t, a_t, r_t, O_{t+1})` 里的 `O_{t+1}` 与 `r_t` 错位一个步长。
修法是 `PolicyObsRing`（复用 W12 的 `ObservationBuilder`，只挪 push 时机），
并用"环 vs `env.step()` 逐位相同"的自检把它钉住（实测 `max|Δ| = 0.0e+00`）。

## §7 已知局限与下一步

**局限（写清楚，免得被误读）**

1. **末端指标"过线但不宽裕"**：盘上这次 0.8651 cm（后 8 次评估均值 0.9240，波动区间 0.86–1.02 cm），
   离冲刺线 0.5 cm 还很远。**"最好那次权重会丢"这个问题已修**：脚本现在在每个评估点比较末端 RMSE，
   刷新就额外存一份 `logs/<run>/policy_best_ee.pt`（`--no_best_ckpt` 可关；JSON 里 `best_ee_checkpoint`
   给出最好点的 cm / rad / 步数，history 每行有 `best_ee_cm_so_far` 单调不增的轨迹）。
   注意：**主结果已经按 §1.4 那条命令重跑过**，所以 `logs/w13_residual_sac_ee50k/policy_best_ee.pt`
   就是最好那一次评估（**0.8612 cm @ 400 384 步**）的 Actor + 归一化统计量；臂 A / 臂 B 两次训练早于这个功能，
   目录里只有 `policy_final.pt`（想补齐，用同样的命令重跑即可）。
2. **奖励里的两项补充（`w_mag`、`w_ee`）不是任务书原话**：`w_mag=0.05` 是必须的（§6.2 的激励漏洞），
   `w_ee=20000` 是"把验收指标写进奖励"的选择。两者都留了开关，对照臂（严格四项）已落盘可比。
3. **策略是"平均补偿器"**：所有 env 共享一个策略，观测里没有 env 身份，而 64 路失配参数各不相同 ⇒
   只能学出"对分布平均最优"的补偿；想更进一步要么让观测含失配线索（如 `τ_prev` 的历史更长、
   或加"最近误差积分"这类特征），要么用 recurrent/context 结构。
4. **观测的记忆能力有限**：H=3 帧、无循环结构 ⇒ 静态偏差（负载重力矩）只能靠"当前 q_d 的函数"近似，
   真正的积分类补偿（`∫e dt`）学不出来。§6.4 的 j6/j5 提升主要来自**摩擦（速度相关）**那一部分。
5. **`dt = 10 ms`**：与 W12 同一口径（便于横比），但真机控制器普遍 1 kHz；步长越小，残差越能"细腻"补偿。
6. **训练预算仍然偏小**：主结果 13 438 次梯度更新、臂 A 8 750 次（W9 的 Pendulum 用了 4 万次）。
   曲线在 200k 之后基本走平，但**没有做收敛性判定**（没有多 seed、没有学习率/UTD 扫描）；
   结合局限 7 的 ±3~5% 重复抖动，**单次运行的数字不该被当成精确值**。
7. **重复运行不是逐位一致**：同一条命令两次运行的**前两次评估（25k / 50k）逐位相同，75k 起分叉**
   （首跑 0.043342 rad / 0.9107 cm，重跑 0.045955 rad / 0.8651 cm）。这是 GPU kernel 的非确定性，
   不是代码或数据的问题 —— 脚本自带 `--deterministic` 开关（`cudnn.deterministic` +
   `use_deterministic_algorithms`），打开可换成"更慢但可复现"的模式，代价是吞吐下降。
   因此**本报告只保证"统计可复现 + 对账链逐位为 0"**：W12 对账、零残差等价性、obs 环自检、
   FK 对账、权重读回在两次运行里给出的偏差都是 `0.00e+00`（§5 第 10 条）。
