## 1. 为什么必须重做一套评测（而不是复用 W13 的评估）

W13 的评估回答的是"我的残差策略比**我自己的**基座好多少"，它跑在**训练用的那一条 DR 采样**上。
论文矩阵要回答另外三个问题，因此必须把"力矩怎么算"**唯一地**独立出来：

1. **同一个失配分布下，四种控制器谁好、好多少**（Table 1）；
2. **失配超出训练分布以后，谁先崩**（Figure 3）；
3. **框架里每个组件是否必要**（Table 2）。

做法：新建 `experiments/w15_paper_benchmarks.py`，把 W13 的引擎块（环境 / FK / DR / 观测 / 奖励 /
基座控制器 / MDP / 残差策略 / 回放池 / 训练循环 / 权重存取）**逐字切片**进来（文件里每一块都有
`[拷贝自 W13 · 第 x-y 行]` 的横幅），只在最外层新增三样东西：

* :class:`ControllerBundle`：四个控制器的差别**只在这里**（基座模式 / 有没有策略 / 动作缩放）；
* :class:`UnifiedMetrics`：**四个控制器共用同一份指标累加器**（口径不同 ⇒ 假差异，这条不允许存在）；
* `stage_*` 三个赛程 + `NominalModel`（见 §4 的两个坑）。

`--stage baselines` 会自动用 **W12 的 `run_episode`** 再跑一遍 `pd_dr` / `pd_ff_dr`，与新循环逐字段对账，
判据是相对偏差 ≤ 1e-9。实测 **0.00e+00**（逐位相同）——这是"Table 1 里那两行仍然等于 W12/W13 报告里
那两个数"的硬证据：

```
[CHECK] 统一循环 vs W12 run_episode（pd_dr）：关节 RMSE 0.060948 vs 0.060948（rel 0.00e+00）| 末端 2.3016 vs 2.3016 cm
[CHECK] 统一循环 vs W12 run_episode（pd_ff_dr）：关节 RMSE 0.051866 vs 0.051866（rel 0.00e+00）| 末端 1.3259 vs 1.3259 cm
```

## 2. 四个控制器（Table 1）与公平性约定

| 编号 | 名称 | 控制律 | 说明 |
| --- | --- | --- | --- |
| C1 | `pd_dr` | `τ = Kp(q_d−q) + Kd(q̇_d−q̇)` | 无模型先验，纯反馈 |
| C2 | `pd_ff_dr` | `τ = Ĝ_nom(q) + Kp(q_d−q) + Kd(q̇_d−q̇)` | 工业界最常见的"标称前馈 + PD"，控制器**不知道**负载 |
| C3 | `pure_rl` | `τ = clip(scale ⊙ tanh(π_φ(o)), ±τ_lim)`，`τ_base ≡ 0` | 切断经典控制器，SAC 直接输出**全部**关节力矩 |
| C4 | `residual_sac`（Ours） | `τ = clip(Ĝ_nom + Kp(q_d−q) + Kd(q̇_d−q̇) + Δτ, ±τ_lim)`，`|Δτ|≤1.5 N·m` | 双层残差：基座兜底 + 上层补偿动态残差 |

公平性（写进论文方法节前必须交代的五条）：

1. **奖励完全一致**：含 `--w_ee 50000` 的末端项与 `--w_mag 0.05` 的残差幅值正则 —— 对比的是**架构**，
   不是奖励工程；
2. **训练预算一致**：45 万环境步、64 路并行、同一随机种子；
3. **观测一致**：同一个 105 维 H=3 时序观测（pure_rl 也照给，不给它"额外照顾"）；
4. **失配分布一致**：同一条 DR 采样实现；
5. 评估一律**确定性**（`tanh(μ)`）、`torch.no_grad()`、不写回放池、不更新归一化统计量。

pure_rl 唯一一处不可避免的设计选择（不藏，写进 JSON 的 `warmup_res_scale`）：

> 热身期随机动作的幅值按**满量程比例**给。残差策略的热身是 1.0 N·m / 1.5 N·m 动作空间 ≈ 67% 满量程；
> 纯 RL 的动作空间是 ±τ_lim（j1–j4 87、j5–j7 12），沿用 1.0 N·m 的话**连手臂自重都撑不住**
> （热身期就塌到关节限位，后面学的全是"从限位爬回来"）。因此取 `0.2 × max(τ_lim) ≈ 17.4 N·m`
> （逐关节再被自己的 scale 夹住）。这是**唯一**一处对 pure_rl 的特殊处理，且它对 pure_rl 是**有利**的。

## 3. 指标口径（四个控制器共用一份累加器）

| 指标 | 定义 | 单位 | 对应 W12/W13 的哪一行 |
| --- | --- | --- | --- |
| 关节跟踪 RMSE | `sqrt(mean_t (q_j−q_{d,j})²)`，先逐 env 逐关节再跨 env 取均值 | rad | `run_episode` 的 `acc_sq` |
| 末端笛卡尔 RMSE | `sqrt(mean_t ‖p(q)−p(q_d)‖²)` | cm | 同上（`ee_err_m`，t 时刻位姿差） |
| 最大瞬时末端误差 `e_max` | `max_{t,e} ‖p(q)−p(q_d)‖` | cm | `acc_ee_max` |
| 平均力矩范数 | `mean_t ‖τ_t‖₂` | N·m | `BaselineController.abs_tau_per_joint` 同源 |
| 控制抖动（jerk） | `mean_t ‖τ_t−τ_{t−1}‖²`（τ_{−1}=0） | N·m² | `MultiObjectiveReward` 的 jerk 项 |
| 饱和步占比 | 任一关节 `|τ| ≥ τ_lim−1e-9` 的步数比例 | — | `stats().sat_step_frac_any_joint` |

**τ 一律取"真正下发到关节的那个力矩"**（延迟压测下 = 延迟线的输出），否则延迟的影响会被统计掩盖。

## 4. 压测怎么"钉死"除自变量以外的失配（含两个必须知道的坑）

`DynamicsRandomizer` 就是"按 seed 从区间采样 → 写进 PhysX"，所以压测点 = **换一组区间 + 同一个 seed +
重新注入**。默认规则（`--stress_fix` 可逐项覆盖）：

| 压测轴 | 自变量 | 其余失配 |
| --- | --- | --- |
| 载荷 | `payload_mass = (m, m)`，m ∈ 0 / 1.5 / 3 / 4 / 5 kg | 连杆 ×U(0.8,1.2) + 阻尼/摩擦 = 训练区间（照原样） |
| 摩擦 | damping 与静摩擦**同时** ×mult，mult ∈ 1 / 1.5 / 2 / 3 | 载荷钉死 1.5 kg（训练区间中点）+ 连杆 ×U(0.8,1.2) |
| 延迟 | `--action_delay` ∈ 0 / 1 / 2 / 3 步（10 ms/步） | 全部失配 = 训练分布（就是训练时那一套） |

延时的物理含义：控制器算出 `τ_t` 后**不是立刻下发**，而是经过一条长度 N 的 FIFO（N 步前的力矩此刻才
到达关节）。延迟线在 episode 开始时用首步力矩**预填**（等价于"这条链路实验开始前就在跑"），因此不会
引入额外的起步瞬态；`N = 0` 时与 W13 的评测逐位相同。

### 4.1 坑一：`DynamicsRandomizer.apply()` 在同一进程里连续调用会**累积**（W15 发现并修掉）

W13 的 `apply()` 实现里，每次注入都先把**当前** PhysX 状态读进来当 nominal，再乘这一轮的采样系数：

```python
m0 = robot.data.body_mass.torch.clone()      # ← 注释写的是"注入前的标称值"
self.nominal_mass = m0                        #   但连续调用时它已经是上一轮注入后的值了
m = m0 * self.mass_scale                      # ← 于是质量被乘两次、未知负载被叠两次
```

W12/W13 一个进程只注入一次，所以从没暴露；W15 的压测要在**同一进程里连续注入十几个点**
（载荷 5 点 + 摩擦 4 点 + 延迟 4 点 + 每段赛程的起点），第一次跑出来的"压测曲线"就成了
"越压越重的假曲线"——同一组采样参数连注入三次，手部质量均值 **2.173 → 3.681 → 5.224 kg**
（第一版数据因此全部作废，已重跑）。

修法：:class:`NominalModel` 在**第一次注入之前**把连杆质量/惯量/质心快照下来，每次注入前先 `restore()`。
并且加了一条**回归自检**（每次运行都会跑）：同一组区间连注入两次，PhysX 回读值必须逐位相同 ——

```
[CHECK] DR 注入幂等性：两次注入回读最大偏差 0.000e+00 -> 通过（同一组参数 ⇒ 同一个物理模型）
```

### 4.2 坑二：训练用的归一化统计量必须跟着**这一次**的观测维度走

消融 1 会把历史长度从 H=3（105 维）换成 H=1（35 维）/ H=5（175 维）。训练变体时如果评估回调里
仍然沿用上一轮 `rig` 上的 `RunningMeanStd(105)`，评估就会直接维度不匹配（实测 `RuntimeError:
The size of tensor a (35) must match the size of tensor b (105)`）。修法：`train_policy` 把
**本次训练**的 `agent` / `normalizer` 显式挂到 bundle 上（与 W13 `evaluate()` 用同一份统计量同理），
并在消融赛程收尾把 rig 恢复成"主结果权重 + 主历史长度"的干净状态。

| --- | --- | --- | --- | --- | --- | --- | --- |

| **双层残差 SAC（C4, Ours）** | **0.045967** | **0.8612** | **2.458** | 39.842 | 2182.6 | 0.000 | −24.278 |

**先看对账**：前两行与 W12/W13 报告里的数字**逐位相同**，不是"差不多"：

```
[RESULT] train_distribution  pd_dr     关节 RMSE = 0.060948 rad | 末端 RMSE = 2.3016 cm   ← W12: 0.060948 / 2.3016
[RESULT] train_distribution  pd_ff_dr  关节 RMSE = 0.051866 rad | 末端 RMSE = 1.3259 cm   ← W12: 0.051866 / 1.3259
[CHECK] 统一循环 vs W12 run_episode：pd_dr rel 0.00e+00；pd_ff_dr rel 0.00e+00 → 通过
```

**四条结论**：

1. **Ours 把末端误差压到 0.8612 cm，相对"工业界标准做法"（标称前馈 + PD）改善 35.0%（×1.54）**，
   关节误差 0.051866 → 0.045967 rad（−11.4%）。这正是 W13 主结果里的**同一份权重**
   （`policy_best_ee.pt`，末端 0.8612 cm @400384 步）——W13 的单点结论在统一评测口径下复现了，
   而且现在有了一张四行对比表。
2. **算力代价几乎为零**：平均力矩范数 39.842 vs 39.364 N·m（+1.2%），饱和步占比两者都是 0.000 ——
   残差策略不是靠"更用力"换精度。
3. **抖动是唯一的代价**：2182.6 vs 1976.8 N·m²（+10.4%）：1.54× 的精度改善换来 1.10× 的抖动。
   这项差异全部来自 `Δτ` 自身的变化（基座那一份两者完全相同）⇒ 想再压抖动就该动 `--wj`，
   这正是消融 3 要回答的问题（见 §7）。
4. **纯 RL（切断经典控制器）在同一预算下彻底失败**：末端 86.4318 cm、`e_max` 152 cm、饱和步占比
   **95.8%**、平均力矩范数 160 N·m（是 Ours 的 4 倍）——甚至比 W12 的**零力矩**基线（73.18 cm）还差。
   三条诊断（都在日志里有对应数字）：

   * **预算量级不对**：45 万环境步 / 64 env = 每个环境只有 ≈7000 步 ≈ **14 条 episode**；纯力矩控制
     从零学 7 个力矩通道的时序协调通常要**百万到千万级**环境步（残差策略只需学"补差量"，
     基座已经把它放在 1.33 cm 的起点上）；
   * **起点是"零输出"**：SAC 的 Actor 头 1e-3 增益初始化 ⇒ `tanh(μ)≈0` ⇒ 第一次评估的 `‖τ‖` 只有
     0.069 N·m（日志 `[RESULT] pure_rl@25024 … ‖τ‖ = 0.069`），策略得先"发现"要发力；热身期的
     随机力矩（±17.4 N·m）撑不住 7 关节自重，误差一度涨到 3.1 rad；
   * **没有安全兜底 ⇒ 饱和吃掉探索**：训练中后期 85–98% 的步都在撞力矩上限
     （评估时 `tanh 饱和占比 = 0.609`、`|Δτ| 均值 = 49.4 N·m`），回报被 `−w_τ‖τ‖²` 与位置项双向撕扯，
     收敛到"用力乱顶"的局部解。

   **这正是本工作要论证的核心：把经典控制器放进环路（残差结构）才是让 RL 在机械臂力矩控制上
   数据高效的关键** —— 同样的 45 万步，纯 RL 连"站住"都没学会，残差 RL 已经把误差压到毫米级。

### 6.1 超载（Out-of-Distribution Payload）

| 载荷 [kg] | PD | PD+FF | **Ours** | Ours / PD+FF | Ours 的绝对领先 [cm] | 饱和步占比（三者） |
| --- | --- | --- | --- | --- | --- | --- |
| 0.0 | 1.5963 | 0.8590 | **0.4960** | 0.577 | −0.363 | 0 / 0 / 0 |
| 1.5（训练中点） | 2.2966 | 1.2805 | **0.7823** | 0.611 | −0.498 | 0 / 0 / 0 |
| 3.0（训练上限） | 3.0316 | 1.9380 | **1.4607** | 0.754 | −0.477 | 0 / 0 / 0 |
| 4.0（**OOD**） | 3.5166 | 2.3998 | **1.9696** | 0.821 | −0.430 | 0 / 0 / 0 |
| 5.0（**OOD**） | 3.9914 | 2.8571 | **2.4748** | 0.866 | −0.382 | 0 / 0 / 0 |

* **残余策略在全部 5 个载荷点都是最优**，且**没有一个点出现饱和**（手腕 τ_lim=12 N·m 在 5 kg 下仍有余量）
  ⇒ 这条轴测的是**控制质量**，不是硬件边界；
* 载荷 0 → 5 kg，三者误差都单调变大（PD ×2.5、PD+FF ×3.3、Ours ×5.0）；
* **相对优势随载荷缩小（0.577 → 0.866）**：因为 `|Δτ| ≤ 1.5 N·m` 是**定值**，而未补偿的重力矩随载荷线性增长
  ⇒ 残差能"补差量"的比例越来越小。**但绝对领先几乎不变（0.36–0.50 cm）**：
  这一点比"相对倍数"更诚实，也更适合写进论文（说"更宽裕度"是过度解读，说"整条曲线下移 ~0.4 cm"是数据支持的说法）；
* 论文里若要论证"残差补偿的裕度更宽"，正确做法是把 `--res_limit` 也放大（消融 2 已经在做），
  而不是只看这张图。

### 6.2 关节摩擦 / 阻尼退化（Friction Anomaly）

载荷钉死 1.5 kg，`joint_damping ∈ 0.5–2.0` 与静摩擦 `∈ 0.1–1.0 N·m` **同时 ×mult**：

| ×mult | PD | PD+FF | **Ours** | Ours / PD+FF | 抖动（PD / PD+FF / Ours）[N·m²] |
| --- | --- | --- | --- | --- | --- |
| 1.0 | 2.2966 | 1.2805 | **0.7823** | 0.611 | 1948 / 1915 / 2083 |
| 1.5 | 2.3915 | 1.4047 | **0.9050** | 0.644 | 1701 / 1525 / 1594 |
| 2.0 | 2.4864 | 1.5421 | **1.0723** | 0.695 | 1240 / 1113 / 1030 |
| 3.0 | 2.6663 | 1.7955 | **1.4342** | 0.799 | 395 / 352 / **282** |

* 三个控制器都**没有崩**：摩擦 ×3（静摩擦最大 3 N·m）只把末端误差抬高 0.37–0.65 cm ——
  因为 PD 基座的回路增益很高（ωn = 30 rad/s），摩擦是**有界扰动**，不是失稳源；
* Ours 依然每一点最优，且**抖动随摩擦增大反而下降**（2083 → 282 N·m²）：摩擦在这里起的是
  **被动阻尼**作用，把 W13 提过的"静摩擦诱发极限环/粘滑"压下去了；到 ×3 时 **Ours 的抖动最低**
  （282 vs 352 vs 395），这是 H=3 时序观测能"看见"阻滞变化的一个旁证（详见 §7 的历史长度消融）。

### 6.3 通信与控制时延（Latency / Phase Lag）

| 延迟 | PD | PD+FF | **Ours** | Ours / PD+FF | 饱和步占比（PD / PD+FF / Ours） |
| --- | --- | --- | --- | --- | --- |
| 0 步（0 ms） | 2.3016 | 1.3259 | **0.8612** | 0.650 | 0.000 / 0.000 / 0.000 |
| 1 步（10 ms） | 2.3151 | 1.3692 | **0.9588** | 0.700 | 0.010 / 0.008 / 0.005 |
| 2 步（20 ms） | 2.8346 | 1.8811 | **1.6469** | 0.875 | 0.382 / 0.354 / 0.224 |
| 3 步（30 ms） | 4.2299 | 3.4635 | **3.3539** | 0.968 | 0.715 / 0.710 / **0.491** |

* **延迟 0 步那一行与 Table 1 逐位相同**（0.8612 cm / 1.3259 cm / 2.3016 cm）——评测管线确定性的又一处证据；
* 10 ms 几乎无影响（+0.01…+0.10 cm）；**20 ms 是拐点**（三者的饱和步占比从 ~0 跳到 0.22–0.38，
  抖动翻倍到 ~4000 N·m²）—— 闭环带宽 ωn = 30 rad/s 在 20 ms 延迟下相位裕度被吃掉一部分；
* **30 ms 时 Ours 的优势基本消失（0.968）**：此时误差主要由**执行器饱和**主导
  （饱和步占比 0.49–0.72），而不是控制律本身 ⇒ 这一档应该作为"时延容忍边界"来报告，
  而不是"控制器优劣"的证据。附带一个可用的细节：即便误差接近，**Ours 的饱和步占比最低（0.491 vs 0.710/0.715）**
  —— 同样的精度用的是更少的饱和，这对真机（电流/热保护）是有意义的。

### 7.1 消融 1：时序历史长度 H（H=1 单帧 / H=3 Ours / H=5）

命令：`--stage ablation --ablation_dims history --total_steps 450000`（用时 1257 s；H=3 那一格复用主结果权重）。

| 变体 | 观测维度 | 关节 RMSE [rad] | 末端 RMSE [cm] | `e_max` [cm] | 抖动 [N·m²] | 饱和 | 相对 Ours |
| --- | --- | --- | --- | --- | --- | --- | --- |
| H=1（单帧，无时序记忆） | 35 | 0.044895 | 1.1313 | — | 310.0 | 0.000 | +31.4% |
| **H=3（Ours）** | 105 | **0.045967** | **0.8612** | 2.458 | 2182.8 | 0.000 | — |
| H=5（历史更长） | 175 | 0.048383 | 1.2859 | — | 305.3 | 0.000 | +49.3% |

**结论：H=3 是"时序信息量 ↔ 输入维度"的甜点值，两端都显著变差。**

* **H=1（31% 更差）**：单帧观测只给"此刻误差 + 上一步力矩"，策略**看不见**摩擦力矩的来龙去脉
  （粘滑是先积累再突跳的），只能学到"接近静态的平滑输出"（抖动从 2182.8 掉到 310.0 N·m²）——
  平稳但跟不上参考；
* **H=5（49% 更差）**：历史更长本应信息更多，但观测维度从 105 涨到 175，在**同一 45 万步预算**下
  样本效率被摊薄（同样的网络容量要拟合更高维的输入分布），结果还不如 H=3；
* 注意 H=1/H=5 的关节 RMSE（0.0449 / 0.0484）都**不差**，甚至 H=1 的关节指标比 H=3 更好
  （0.044895 vs 0.045967）——但末端指标差 31%。这正是 W13 §6.2 那个结论的又一次体现：
  **关节空间各向同性的奖励 ≠ 末端验收指标**，所以消融必须看末端那一列；
* H=3 的"敢动"程度也最高：平均 |Δτ| 1.001 N·m、tanh 饱和占比 19.8%（H=1 是 0.850 / 5.5%，
  H=5 是 0.865 / 5.2%）——**在同样的 ±1.5 N·m 约束下，只有 H=3 的策略有足够信息去"用满"动作空间**。

### 7.2 消融 2：残差动作限幅 |Δτ|（±0.5 / ±1.5 Ours / ±5.0 N·m）

|Δτ| 的逐关节缩放（`--res_scale_mode kp`：`scale_j = min(res_limit, 0.2·Kp_j)`）：

| res_limit | 逐关节 scale [N·m] | 末端 RMSE [cm] | 实际用掉的比例 | 平均 \|Δτ\| [N·m] | tanh 饱和占比 |
| --- | --- | --- | --- | --- | --- |
| ±0.5 | 全部 0.50 | 1.3344（+54.9%） | 66% | 0.330 | 7.2% |
| **±1.5（Ours）** | 1.5×6 + 0.52（j7） | **0.8612** | 67% | 1.001 | 19.8% |
| ±5.0 | 5.0×5 + 4.84(j5) + 0.52(j7) | 1.7040（+97.8%） | 53% | 2.663 | 9.1% |

* **两端都变差，是一个清晰的 U 形**：
  * **±0.5（补偿不足，+54.9%）**：这一档的残差被压到 0.5 N·m，而 W11/W12 量到的失配量级是
    静摩擦 0.1–1.0 N·m、阻尼 ≤2 N·m·s/rad、3 kg 负载的静态重力矩 ~10 N·m ⇒ **补不动**，
    策略把 66% 的量程都用满了（0.330/0.500）还是不够；
  * **±5.0（补偿过大，+97.8%）**：这一档的残差在 j1–j5 上放到 5 N·m（j5 的硬件上限才 12 N·m），
    策略平均用到 2.663 N·m —— 与 W13 §6.1 里那个"奖励激励漏洞"同源：`‖τ_exec‖²` 项鼓励
    **抵消基座力矩**，动作空间一大，残差就开始与基座对打，末端误差反而翻倍。
    **结论：约束动作空间（±1.5 N·m）不是"保守"，而是这份奖励结构下的必需品** —— 这正是任务书
    消融 2 要回答的问题，答案是"必须约束，且 1.5 N·m 是甜点"。
* 佐证：±5.0 的实际使用率只有 53%、tanh 饱和只有 9.1%（不是"够不着上限"，而是"用到 2.6 N·m 就开始伤性能"）。

### 7.3 消融 3：抖动惩罚项 w_j（0 vs 0.01 Ours）

| w_j | 末端 RMSE [cm] | 抖动 [N·m²] | 平均 \|Δτ\| [N·m] | tanh 饱和占比 |
| --- | --- | --- | --- | --- |
| 0（去掉） | 1.2199（**+41.7%**） | **417.6** | 0.857 | 7.5% |
| **0.01（Ours）** | **0.8612** | 2183.0 | 1.001 | 19.8% |

**这一组的结果与"去掉 jerk 惩罚 ⇒ 力矩高频振颤"的直觉相反，必须如实报告**：

* 去掉 jerk 项后末端误差**差 41.7%**（1.2199 vs 0.8612 cm），**但抖动量测值反而更低**（417.6 vs 2183.0 N·m²）；
* 可观测量给出的一致解释是"**策略变懒**"：w_j=0 时平均 |Δτ| 0.857 N·m、tanh 饱和占比 7.5%
  （Ours 是 1.001 / 19.8%）⇒ 去掉这一项之后，策略收敛到**更被动、更滞后**的解（误差更大、
  轨迹更慢更平滑），所以"力矩变化率"自然更低；
* 另一个必须交代的口径问题：这里的 jerk 是 **τ_exec = τ_base + Δτ** 的变化率，而 τ_base 的形状
  取决于**闭环轨迹**。参照量级：Δτ ≡ 0 的 `pd_ff_dr`（Table 1）jerk = 1976.8 N·m²，
  Ours = 2182.6 ⇒ **Δτ 只贡献了 ~10%**；w_j=0 的 417.6 说明它的 τ_base 本身平滑得多
  （因为跟踪变差、动作变慢），而不是"残差更平滑"；
* ⇒ **本实验能支持的结论是**：jerk 惩罚项在这一套奖励里起的是"**不让策略退化成被动解**"的作用
  （它挡在 `−w_τ‖τ‖²` 那个"缩小力矩"的压力前面），而**不是**"直接产生平滑力矩"。
  论文里如果要主张"该项带来物理平滑"，正确做法是补一张 **Δτ 变化率 vs τ_base 变化率的分项分解表**
  （本脚本已经逐项落盘 `reward.raw_squared_per_step_mean`，只差一个"分项 jerk"累加器），
  或者干脆改用显式的动作变化率正则（W13 的 `--w_mag` 就是同族手段）。

## 9. 限制与后续（写进论文的 Limitations，也是下一轮的 TODO）

1. **纯 RL 的预算是"同一预算"，不是"它需要的预算"**。§5 的 86.43 cm 只能说明"在 45 万步这个量级上，
   纯 RL 不可用"，**不能**说明纯 RL 学不会这个任务。要给出公平的上限，应该再跑 `--pure_rl_steps 2000000`
   （约 40 min）并在论文里明确写清预算。
2. **饱和在载荷轴上没有出现，但在延迟轴上会主导结果**。实测载荷 0→5 kg 三个控制器的饱和步占比
   全程 0.000（手腕 12 N·m 在 5 kg 下仍有余量），所以载荷轴是干净的"控制质量"轴；反过来，
   延迟 ≥2 步时饱和步占比冲到 0.22–0.72，30 ms 那一档三个控制器误差接近（3.35–4.23 cm）
   其实是**执行器限幅**造成的，不能当成"控制器优劣"来解读 —— 论文里报延迟轴时必须同时给饱和步占比
   （本报告与 CSV 里都有这一列）。
3. **延迟压测目前只做了"定值延迟"**，没有做时变延迟 / 抖动的延迟分布（更接近真实 EtherCAT/网络链路）。
   实现上只需把 `ActionDelayBuffer.steps` 换成每步重采样（代码位置已注释）。
4. **消融只覆盖了任务书要求的三组**（H / 残差限幅 / jerk 惩罚项）。框架里还有两个值得加的：
   奖励里的 `w_ee`（末端项）与 `w_mag`（残差幅值正则）—— W13 §6 已经指出它们改的是"奖励结构与验收
   指标的错配"，但还没在统一口径下量化。
5. **摩擦轴目前是"同倍率放大阻尼与静摩擦"**。更严格的做法是分别扫 damping / static / dynamic
   摩擦（PhysX 三个参数都可独立写，`DynamicsRandomizer.apply()` 已经全部覆盖），可以分离"黏滞"与
   "库仑"两类退化的影响。
6. **没有做随机种子的重复实验**（本报告每个点只跑一个种子 42）。同一命令重跑会因 GPU 内核非确定性
   在评估点之间产生微小差异（W13 §7 已量过：同一份权重两次运行的差异在 1e-3 相对量级），
   论文定稿前应把关键点跑 3 个种子并给出均值±标准差。
