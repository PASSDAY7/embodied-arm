## §1 任务与交付物

### 1.1 任务要求（W12 Day 3）

1. **时变参考轨迹发生器**：关节空间复合正弦 `q_{d,i}(t) = q_{0,i} + A_i sin(2π f_i t + φ_i)`，
   自动解析给出 `q̇_d`、`q̈_d`；
2. **标准 MDP 观测空间**：`s_t = [e_q, ė_q, q_d, q̇_d, τ_{prev}]`，其中 `e_q = q − q_d`、`ė_q = q̇ − q̇_d`；
3. **时序历史缓冲**：保留过去 `H = 3` 步的观测拼接（隐式推断未建模摩擦与外载荷的基石）；

   权重初值 `w_p = 10.0, w_v = 0.1, w_τ = 0.001, w_j = 0.01`；
5. **开环基线追踪探针**：用 `τ_base = K_p e_q + K_d ė_q` 在**启用了 W11 动力学随机化**（未知负载 + 摩擦）
   的 **64** 个环境里跑 **500** 步，输出**关节跟踪 RMSE** 与**末端笛卡尔跟踪误差（cm）**。

## §2 MDP 环境设计

### 2.1 时变参考轨迹发生器（`TrajectoryGenerator`）

```python
q_{d,i}(t) = q0,i + Σ_{h=1..K} A_{i,h}·sin(2π f_{i,h} t + φ_{i,h})
q̇_{d,i}(t) = Σ_h A_{i,h}ω_{i,h}·cos(...)          ω = 2π f
q̈_{d,i}(t) = −Σ_h A_{i,h}ω_{i,h}²·sin(...)
```

* **解析导数**：`q̇_d / q̈_d` 是闭式解，不做差分（奖励里的速度误差项直接用它，评测时也不用担心数值微分噪声）；
* **逐关节独立采样** `(A_i, f_i, φ_i)`：主实验实测 `A = [0.326, 0.333, 0.227, 0.342, 0.228, 0.270, 0.201] rad`、
  `f = [0.517, 0.576, 0.253, 0.574, 0.437, 0.548, 0.427] Hz`、`φ = [4.656, 2.698, 5.563, 3.606, 1.675, 3.942, 1.694] rad`
  —— 7 个关节周期互不相同，这才叫"多轴连续插补"；若所有关节同相位同频率，整臂会像一块刚体一样摆动，
  误差同相叠加，指标好看但不真实；
* **幅值按关节限位自动 clamp**（`--traj_margin 0.8`）：`Σ_h A_h ≤ 0.8·min(q0−lo, hi−q0)`。
  实测 `amp_clamp_ratio = 1.0`（默认幅值没触发 clamp），全 episode 离限位最近 **0.930 rad**，
  而且这个数是 `check_limits()` 在**整个 episode 网格上逐点实测**出来的，不是估的；
* **`--harmonics K`**：K=1 时严格等于任务书公式；K>1 时叠加 2f、3f…（幅值按 1/h 衰减），
  用来造更宽频的参考（对未建模摩擦激励更强）。
* **所有 env 共享同一条参考轨迹**：跨 env 的误差差异就只能来自动力学差异 —— 这正是 W11 注入的失配。

> **参考中心 q0 是"实测定出来的"，不是随手写的**（`--traj_center` 默认 `[0, −0.4, 0, −1.8, 0, 1.8, 0]`）：
> 先试过两组合成的"肘部姿态"和"限位中点姿态"，前者关节限位余量只有 0.26–0.33 rad，
> 轨迹跑到极值处**实际关节撞上限位**，PD 在限位约束上打出一记 bang-bang（trace 里 t≈1.2 s 时
> 关节 RMS 从 0.03 rad 瞬间涨到 0.29 rad、单步回报从 −0.4 掉到 −410），把指标污染成"饱和指标"；
> 后者（限位中点）手臂水平伸展、重力矩最大，手腕力矩顶到 12 N·m 上限，指标同样不能用。
> 最终选的这一组：**限位余量 ≥1.27 rad（参考轨迹绝对撞不到限位）且手腕重力矩只剩 ~6 N·m**（离上限有余量）。

### 2.2 观测设计 + 时序历史缓冲（`ObservationBuilder`）

单帧 `s_t`（35 维）的切分表（脚本里会原样落盘，避免"维度对不上"的扯皮）：

| 切片 | 含义 | 维度 | 说明 |
|---|---|---|---|
| `0:7` | `e_q = q − q_d` | 7 | 位置跟踪误差 [rad] |
| `7:14` | `ė_q = q̇ − q̇_d` | 7 | 速度跟踪误差 [rad/s] |
| `14:21` | `q_d` | 7 | 期望关节位置（告诉策略"现在该在哪一段"） |
| `21:28` | `q̇_d` | 7 | 期望关节速度（前馈信息；没有它策略得自己差分） |
| `28:35` | `τ_{t−1}` | 7 | 上一步力矩（隐式推断未建模摩擦/外载 + 抑制抖动） |

**历史缓冲**：`obs_t = [s_{t−H+1}, …, s_{t−1}, s_t]`（**旧 → 新**，最后 35 维是当前帧），`H = 3` → **105 维**。
实现是 `H` 个预分配缓冲的**环形队列**：稳态下每步一次 `copy_` + 一次 `cat`，没有累积分配。

**warm-up**（episode 起点历史没填满）默认 `repeat`：用首帧重复填满。为什么不用零：零帧会被策略
误读成"误差为 0 的完美状态"，而 `repeat` 对应"一直在原地不动"的自然语义。`--history_warmup zeros` 可切换。

### 2.3 多目标奖励（`MultiObjectiveReward`）

```
r_t = − w_p‖e_q‖² − w_v‖ė_q‖² − w_τ‖τ_t‖² − w_j‖τ_t − τ_{t−1}‖²      (w_p, w_v, w_τ, w_j) = (10, 0.1, 0.001, 0.01)
```

* **四项分项单独统计落盘**（`reward.terms_per_step_mean`）。只看总回报，四个权重里任何一个跑偏都看不出来；
  分开统计后能一眼分辨"这轮是精度涨了，还是只把力矩压小了"。
* 主实验实测（`pd_dr`，每步每 env 平均）：`pos 0.43`、`vel 0.12`、`tau 1.98`、`jerk 20.23`
  → 当前基线的回报**被 jerk 项主导**（占比 ~89%）。这不是 bug：PD 基线在 100 Hz 下的力矩本身带着
  抖振（手腕力矩 0.03–3.8 N·m 量级来回跳），jerk 项忠实地把它记了下来。Day 4 的 RL 想涨回报，
  第一件事必然是"把力矩磨平"，这正好是 `w_j` 想教的。
* 观测/奖励口径一致性：`e_q` 给的是 `q − q_d`（与任务书一致）；奖励用 `‖e_q‖²`，**与符号无关**。

### 2.4 时序契约（`TrajectoryTrackingMDP.reset/step`）

每一步的严格顺序（写清楚是为了让 Day 4 的 RL 训练能对齐）：

1. `t` 时刻算参考 `q_d(t), q̇_d(t), q̈_d(t)`（所有 env 共享）；
2. 用**当前测得**状态拼单帧 `s_t` 压进历史缓冲 → `obs_t`；
3. 同时算当步的末端误差 `ee_err = ‖FK(q) − FK(q_d)‖`（基座位姿取同一帧，见 §2.5）与 FK 自校验；
4. 外部策略给 `τ_t`（本脚本用 PD，Day 4 换成 RL 策略）→ 写命令 → `sim.step` → `scene.update`；
5. 奖励用 **`t+dt`** 的新状态 + 本步力矩：`r_t = −w_p‖e_q(t+dt)‖² − … − w_τ‖τ_t‖² − w_j‖τ_t − τ_{t−1}‖²`；
6. `terminated ≡ False`（周期轨迹的非终止任务，误差大就体现在奖励上，不提前结束 episode），
   `truncated` 在 `t ≥ steps·dt` 时为 True；`info` 里带 `e_q / ė_q / ee_err_m / reward_terms`。

**episode 起点**：默认 `--init_at_reference`，把关节状态直接初始化到 `q_d(0) / q̇_d(0)`
（去掉起步瞬态，RMSE 才反映"跟踪能力"而不是"起步有多慌"）；`--no_init_at_reference` 可改为从默认位形起步。

### 2.5 末端笛卡尔误差怎么算（本脚本最"硬"的一块）

Isaac Lab 3.0 的 PhysX 后端**没有**"给定关节角求连杆位姿"的接口（`get_link_transforms` 只能拿**当前**状态），
而跟踪误差必须在 `q` 与 `q_d` **两个不同配置**上求末端位置。所以脚本自带一个 **URDF → torch 批量 FK**：

* 从 Isaac Lab 自带的 `isaaclab/controllers/config/data/lula_franka_gen.urdf` 解析
  `panda_link0 → … → panda_hand`（9 段链：7 个转动关节 + `panda_joint8`/`panda_hand_joint` 两个固定关节），
  取每个关节的固定 `origin(xyz, rpy)` 与关节轴；解析失败会退回脚本内嵌的同一组常量并**打印来源**（不静默）；
* 4×4 齐次矩阵在显存里**对全部 env 一次算完**：`T_child = T_parent · T_origin · R(axis, q)`；
* **自校验**：每一步都拿 `FK(q_measured)` 与 PhysX 自己算出来的 `body_link_pos_w` 逐连杆对账，
  主实验 500 步 × 5 scenario 的最大残差 **4.87e-06 m**（默认位形预检 **1.37e-06 m**，阈值 1e-4 m）→ 5 条 scenario 全部 `fk_valid = true`；
  逐连杆残差（默认位形预检）：`panda_link1 1.33e-07 … panda_hand 1.37e-06 m`；
* **末端误差与 env 网格无关**：参考位置用 `FK(q_d)`、实际位置用 `FK(q)`，**同一个基座位姿**做种子，
  两者相减时基座位姿自动抵消，所以误差不含"环境间距/世界原点"的任何成分。

### 2.6 标称重力模型（"前馈"从哪来）

"前馈 + PID"里的前馈 = **重力补偿力矩** `G(q)`。脚本用同一条 FK 链 + **注入前**读到的标称连杆质量/质心，
按虚拟功解析算出来：

```
U(q) = Σ_i m_i·g·z_com,i(q)
G_j(q) = ∂U/∂q_j = Σ_i m_i·g·(a_j × (p_com,i − o_j))_z        # a_j: 关节 j 的世界转轴，o_j: 枢轴点
```

`G_j` 就是 EOM `M q̈ + C q̇ + G = τ` 里的重力项（符号与 PhysX 的 `gravity_compensation_forces` 一致）。
**自校验**：同一模型下两者应当逐关节吻合，实测 max `|ΔG| = 0.220 N·m`（相对 1.11%）。
残留 1% 来自未建模的**手指质量**（两个 finger 连杆挂在手部外侧、不在本链上）—— 属于已知的模型截断，
不是实现错误（`--ff oracle` 可直接读 PhysX 的值对照）。

因为这个 `G(q)` 用的是**标称**质量/质心，它对 DR 注入的负载一无所知 ——
注入后"前馈"就是错的了，误差里恰好量化了"未知负载的重力矩"这一项。

## §3 开环基线控制器（`BaselineController`）

### 3.1 ⚠ 任务书公式里的一个符号坑（可复现）

任务书给的观测定义是 `e_q = q − q_d`，同时写 `τ_base = K_p e_q + K_d ė_q`。
把定义代进去，这个**字面写法**是：

```
τ = K_p·(q − q_d) + K_d·(q̇ − q̇_d)      ← 关节掉到目标下方时给出"往下推"的力矩
```

这是**正反馈**。用 `--pd_sign literal` 严格复现（`docs/results/w12_pd_sign_literal.json`，64 env × 300 步）：

| 符号口径 | 关节 RMSE | 末端 RMSE | 撞力矩上限的步占比 | 单关节饱和率 |
|---|---|---|---|---|
| `literal`（任务书字面写法） | **1.802354 rad** | **57.4749 cm** | **0.990** | 0.966 |
| `stabilizing`（标准 PD，默认） | **0.060948 rad** | **2.3016 cm** | 0.000 | 0.000 |

脚本默认按**标准 PD 口径**实现：`τ = K_p(q_d − q) + K_d(q̇_d − q̇) = −(K_p e_q + K_d ė_q)`。
两个口径只差一个负号，但一个收敛、一个发散。注意这个修正**只影响"控制器怎么用误差"**，
不影响观测（照样给 `q − q_d`）与奖励（`‖e_q‖²` 与符号无关）。

> 为什么值得单独写一节：这个坑在"静态参考 + 关重力"下**完全看不出来**（误差恒为 0，力矩恒为 0），
> 一旦打开重力就变成 1 s 内误差涨到 4 rad、98% 的步在力矩上限。W12 首次跑出来时正是这个现象。

### 3.2 增益不能手填：M 加权增益 vs 对角增益

Franka 的关节等效惯量跨**两个数量级**（主实验 `M(q0)` 对角元实测：
`[0.631, 2.280, 1.281, 0.866, 0.0269, 0.0348, 0.00289] kg·m²` —— 手腕 5/6/7 只有肩关节的 1/100）。
同一组标量 `kp/kd` 用在两者上必然出事。脚本提供两种自动口径：

| 口径 | 增益 | 主实验实测裕度 | 结果 |
|---|---|---|---|
| `--gains mweighted`（默认） | `Kp = ωn²·M̂(q0)`、`Kd = 2ζωn·M̂(q0)`（**矩阵**，计算力矩 PD 的 PD 部分） | `λmax(M⁻¹Kp)dt² = 0.090`、`λmax(M⁻¹Kd)dt = 0.600`（限值 4 / 2） | 末端 RMSE **0.63 cm**（`pd_ff_nodr`） |
| `--gains auto`（对角） | `kp_j = I_jj·ωn²`、`kd_j = 2ζωn·I_jj` | ωn=6：`1.876`（稳，贴近边界）→ **19.39 cm**；ωn=10：`3.126 > 2`（**不稳定**）→ 颤振、**9.86 cm** | 差 15–30 倍 |

关键点：**稳定性由 `M⁻¹Kp` / `M⁻¹Kd` 的特征值决定，不是由单个关节的 `ωn·dt` 决定**。
对角增益看着"每个关节都满足 ωn·dt = 0.6 < 2"，但 M(q) 的强耦合让某些模态的有效惯量远小于对角元，
`λmax(M⁻¹Kd)·dt` 直接冲到 3.13 —— 闭环在力矩上限之间颤振（日志里表现为 `sat_frac` 高、
`jerk` 项大、`velRMSE ≈ 速度上限`）。脚本把这两个裕度**算出来并落盘**（`kpd_gains.multivariable_margin`），
超限时打印 `[WARN]`。

**ωn 与 ζ 的选择**（主实验 `ωn=30 rad/s`、`ζ=1.0`）：这是"离散 D 项稳定性"允许的带宽上界附近
（`λmax(M⁻¹Kd)dt = 2ζωn·dt = 0.6`），再往上加 ζ 就会翻掉（实测 `ζ=2.0` 时手腕颤振、饱和率 30%）；
往下减 ζ 会欠阻尼。100 Hz 下这台机器用 M 加权增益可用的带宽 ~30 rad/s（真机 1 kHz 下能开到 100+）。

### 3.3 力矩饱和与"诚实的指标"

* 每步力矩按 `joint_effort_limits`（肩 87、手腕 12 N·m）**clamp**，并统计
  `sat_step_frac_any_joint` / `sat_entry_frac` / `sat_frac_per_joint` / `mean_abs_tau_per_joint`；
* 主实验 5 条 scenario 的**饱和率全部为 0.0000**（`sat_frac_per_joint` 也是全 0）——
  也就是说"基线值"没有被饱和污染；平均力矩 `|τ| = [5.8, 19.9, 11.6, 26.5, 1.3, 3.8, 0.37] N·m`（`pd_dr`），
  最大关节（joint4，26.5 N·m）离 87 N·m 上限还有 3 倍余量；
* 一旦饱和（例如 `--pd_sign literal` 或对角增益 ωn=10），日志与 JSON 会**直接暴露**：
  饱和率 0.99 / 0.966、`jerk` 项飙到百倍 —— 这几项就是"不要相信这组数字"的报警灯。

### 3.4 五个 scenario

| 名字 | 控制器 | 动力学 | 作用 |
|---|---|---|---|
| `pd_nodr` | PD（M 加权） | 标称 | 无前馈的基线在标称动力学下的水平 |
| `pd_ff_nodr` | PD + **标称模型**重力前馈 | 标称 | "前馈+PID"的**理想上限**（模型完全正确） |
| `pd_dr` | PD（M 加权） | 注入失配 | ★ 任务书要求的基线追踪测试 |
| `pd_ff_dr` | PD + 标称模型重力前馈 | 注入失配 | 前馈模型"不知道负载"时的表现 |
| `zero_dr` | 零力矩 | 注入失配 | 误差上界（完全不控制） |

`--ff oracle` 可把 `pd_ff_*` 的前馈换成直接读 PhysX 的 `gravity_compensation_forces`（**知道真实负载**，
是上限参照，不是控制器的能力）。

## §4 实测结果

### 4.1 主表（64 env × 500 步 × seed 42，`docs/results/w12_tracking_64env.json`）

| scenario | 关节 RMSE [rad] | 最差 env/关节 [rad] | 末端 RMSE [cm] | 末端 MAE [cm] | 末端 max [cm] | 回报/步 | 饱和率 |
|---|---|---|---|---|---|---|---|
| `pd_nodr` | 0.033389 | 0.095757 | 1.4367 | 1.3661 | 2.5796 | −30.81 | 0.0000 |
| `pd_ff_nodr` | 0.015779 | 0.051514 | **0.6269** | 0.4280 | 1.8890 | −31.05 | 0.0000 |
| **`pd_dr` ★** | **0.060948** | 0.273472 | **2.3016** | 2.2558 | 3.9329 | −22.76 | 0.0000 |
| `pd_ff_dr` | 0.051866 | 0.273412 | 1.3259 | 1.2287 | 3.0303 | −22.24 | 0.0000 |
| `zero_dr` | 0.972252 | 2.946950 | 73.1780 | 70.7354 | 92.0173 | −80.95 | 0.0000 |

读法（三条对照链）：

1. **前馈值多少钱**：`pd_nodr 1.44 cm → pd_ff_nodr 0.63 cm`（标称动力学下，把重力前馈补上就翻了一倍多精度）；
2. **失配值多少钱**：同控制器下 `1.4367 → 2.3016 cm`（×1.60，关节 ×1.83）；带前馈时 `0.6269 → 1.3259 cm`
   （×2.12，关节 ×3.29）—— **相对退化更明显**，因为前馈把"已知的重力"拿走之后，
   剩下的误差就是纯失配（摩擦 + 未知负载），正是 Day 4 要学的东西；
3. **不控制会怎样**：`zero_dr` 73.18 cm —— 基线离"完全不控制"还有 30 倍距离，说明这个环境**不是**
   "随便动动就行"，也说明 RL 有巨大可改进空间（但也别指望零力矩那种"几乎不动"的低回报策略：
   `zero_dr` 的回报 −80.95/步 反而是**最差**的之一，因为位置项罚得狠）。

### 4.2 逐关节分解（误差落在谁身上）

`pd_dr` 的逐关节 RMSE：

| 关节 | j1 | j2 | j3 | j4 | j5 | j6 | j7 |
|---|---|---|---|---|---|---|---|
| `pd_nodr` | 0.03999 | 0.01833 | 0.02440 | 0.04928 | 0.02595 | 0.05501 | 0.02077 |
| `pd_dr` | 0.04676 | 0.01999 | 0.03051 | 0.05304 | 0.04405 | 0.06235 | **0.16993** |
| `pd_ff_dr` | 0.03702 | 0.00609 | 0.02278 | 0.00974 | 0.04324 | 0.07387 | **0.17033** |

两个结论：

* **失配主要体现在 `panda_joint7`**：0.0208 → 0.1699 rad（×8.2）。原因很直接 ——
  它的等效惯量只有 `2.89e-3 kg·m²`，所以 M 加权增益给它的 `Kp = ωn²·M = 2.60 N·m/rad`，
  而注入的静摩擦是 **0.10–0.99 N·m**（实测回读 mean 0.554 N·m）→ 光靠位置误差硬顶，
  静态误差就是 `τ_friction/Kp ≈ 0.55/2.60 ≈ 0.21 rad`，量级完全吻合。
  **这是"低惯量关节 + 未建模摩擦"的必然结果，也是残差 RL 最该去补的一项。**
* **前馈只补重力，不补摩擦**：`pd_ff_dr` 把 j2/j4（重力矩最大的两个关节）从 0.0200/0.0530 压到
  0.0061/0.0097，但 j5/j6/j7 几乎没动（0.0432/0.0739/0.1703）—— 因为那三个关节的误差主要来自
  **摩擦**（重力矩本来就小），前馈对它无能为力。

## §6 排错记录（这 4 个坑都真实发生过，脚本里都留了"报警灯"）

1. **任务书公式的符号坑**（§3.1）：`τ = +Kp e_q + Kd ė_q`（`e_q = q − q_d`）是正反馈。
   现象是"重力一开，1 s 内误差涨到 4 rad、98% 的步在力矩上限"。
   现在两种口径都在（`--pd_sign {stabilizing,literal}`），默认收敛口径，可一键复现对照。
2. **对角 PD 增益在 100 Hz 下会颤振**（§3.2）：现象是"跟踪位置误差不大（0.03 rad），
   但 `velRMSE ≈ 速度上限 2.2 rad/s`、`jerk` 项比 `pos` 项大 3 个数量级、关节在 ±力矩上限之间跳"。
   根因是 `λmax(M⁻¹Kd)·dt = 3.13 > 2`。修法是改用 M 加权增益（`Kp = ωn²M̂`）并**把裕度算出来落盘**。
3. **参考轨迹撞关节限位的 bang-bang**（§2.1）：现象是 trace 里出现"误差瞬间涨 10 倍、单步回报 −410、
   然后慢慢恢复"的周期尖峰。根因是参考中心离限位只有 0.33 rad，实际关节被限位约束顶住，
   PD 与约束打架。修法是把参考中心换成"限位余量 ≥1.27 rad 且手腕重力矩小"的实测定标姿态，
   并把限位检查写进脚本（`check_limits`）。
4. **PhysX 的 `M(q)` 是 `simulate()` 里算的**：注入失配后立刻读 `robot.data.mass_matrix` 会拿到**旧值**
   （日志里表现为"注入后倍率 = [1.0, 1.0, …]"这种明显不对的数）。修法是注入后先零力矩空推一步
   （`zero_torque_warmup_step()`，紧接着 `reset()`，不污染 episode 指标），再读 `M`。
5. **argparse 的 help 字符串里不能直接写 `%`**：`--traj_margin` 的说明里有"20% 余量"，
   导致 `--help` 直接抛 `ValueError: unsupported format character`（argparse 会对 help 做 `%` 格式化）。
   写成 `%%` 才对。这个坑是"最后跑一次 `--help` 自检"才发现的 —— **交付前把所有 CLI 入口都点一遍**。

另外两个"看起来像 bug、其实是对"的现象，也一并记下来省得以后重复排查：

* **手腕 `panda_joint7` 误差总是最大**：不是插值/索引错位，而是它 `Kp` 最小（2.60 N·m/rad），
  而注入摩擦 0.10–0.99 N·m 直接落在这儿（§4.2 有量级对账）；
* **回报被 `jerk` 项主导（~89%）**：不是权重写错，而是 PD 基线本身力矩抖振；
  要让它降下来正是 Day 4 的功课。

## §7 已知局限与下一步

**局限（写清楚，免得被误读）**

1. **前馈只有重力**：没有 `M̂·q̈_d + Ĉ·q̇_d` 的惯性/科氏前馈，所以"PD + 重力前馈"仍会随参考加速度
   产生相位滞后与幅值误差（这就是 `pd_ff_nodr` 0.63 cm 而不是 0.01 cm 的原因）。
   真正的计算力矩控制需要**标称 M̂(q)、Ĉ(q,q̇)** —— 目前只用了 `M̂(q0)` 这个常量矩阵。
2. **`M̂`/`Ĝ` 取自注入前的标称模型**：这是**有意的**（要模拟"控制器不知道负载"），
   但也意味着 DR 打开后前馈本身就有偏差；`--ff oracle` 可直接看"知道真实负载"的上限。
3. **重力模型残差 1.11%**：未建模手指质量所致；对 0.6 cm 量级的指标而言可忽略，但对 0.1 mm 级不算。
4. **手指不参与**：观测/奖励/控制都只含 7 个臂关节（手指零力矩自由摆动）。
   如果后续要做"抓取 + 跟踪"，手指要单独设计动作与奖励。
5. **`dt = 10 ms`（100 Hz）**：这个步长下用对角增益只能开到 ωn≈6 rad/s；
   真机控制器普遍跑 1 kHz。若追求更高精度，应把 `--dt` 调小（代价是步数/时间同比例增加）。
6. **单条参考轨迹**：所有 env 共享同一条 `(A, f, φ)`，只做了"同参考、不同动力学"的对照。
   真正训练时要再随机化参考本身（`TrajectoryGenerator` 里预留了"每 env 不同轨迹"的中间维）。

  `Δτ`（叠在 PD + 重力前馈之上），观测直接用现成的 105 维历史向量；
* **对照基准已经就位**：标称 0.63 cm、注入失配 1.33 cm（前馈+PID）/ 2.30 cm（纯 PD）、
  零力矩 73.18 cm。RL 要证明的是"在同样的 64 路随机化环境里，把 1.33 cm 往下压"，
  并且不能靠"把力矩磨平换取 jerk 项"来骗奖励（§4.1 的三条对照链就是防作弊的护栏）；

  失配注入与"同力不同态"见 [`docs/reports/w11_task1_dynamics_randomization.md`](w11_task1_dynamics_randomization.md)。
