## 0. 3 分钟速读版

**一句话**：原来的策略是"看一眼状态，直接算出一条动作"（回归）；这次我把它换成**扩散模型**——
"从一团随机噪声出发，反复擦 16 次，擦出一条合理的动作"，然后**用同一份数据、同样的训练预算**
和原来的回归策略硬碰硬地对比，看扩散到底好在哪、贵在哪。

**结论（先说结论，后面逐条给证据）**：

| 问题 | 答案 |
| --- | --- |
| 扩散真的会"分布采样"吗？ | **会**。在"状态完全看不出该往左还是往右"的玩具任务里，回归策略的输出精确等于 0（两个答案的中间值，一个都不可行），扩散有 **98.5%** 的采样落在真正的两个动作上。 |
| 在倒立摆上扩散赢了吗？ | **没有**。闭环回报 −331.8 vs 回归的 −181.7；每次规划耗时 24.72 ms vs 0.186 ms（**慢 132.8 倍**）。 |
| 为什么没赢？ | 倒立摆里"左右都行"的歧义瞬间只占 **0.95%** 的状态，其余状态已经足够判断方向；扩散的逐次重采样还带来**块间方向翻转（49.2%）**，反而扣分。 |
| 数据少的时候扩散更好吗？ | **不是**，反而更糟（16% 数据：−882.7 vs −204.0）。扩散要先把"两个峰"学清楚，数据不足时它的输出会变钝（采样幅值 1.69 → 0.75）。 |
| 那这套东西有什么用？ | 它量化了"**什么时候该为分布花钱**"：当歧义/多解真正决定成败时用扩散（后续真实机械臂的"多解抓取、绕障"），当歧义只是瞬时噪声时用回归更划算。同时这套代码是可直接复用的最小实现（358k 参数、5.5 分钟训练、15 个单元测试）。 |

## 2. 背景：为什么要搞这么复杂（先讲清楚"痛点"）

### 2.1 先说清楚这个项目在做什么

`embodied-arm` 是一个"从演示中学会控制机械臂"的技术栈。现在的实验对象是 Gymnasium 的
**倒立摆（Pendulum）**：一根摆从下垂位置开始，策略要持续输出力矩 τ 把它甩起来并稳在倒立位置。
奖励是负分制（越接近 0 越好），完全不动大约 −1974，稳一整回合约 −115。

学的方式是**模仿学习里的行为克隆（Behavior Cloning, BC）**：
先让一个"专家控制器"（人工写的规则，不是神经网络）跑很多回合，把 `(状态 s, 专家动作 a)`
一条条记下来，然后让神经网络去模仿——本质就是**监督学习**。

Task 1 已经做了两件升级：① **动作块（action chunk）**：一次预测未来 K=8 步的动作，省推理；
② 各种执行方式（每步重规划 / EMA 平滑）。Task 1 的策略可以写成一句话：

> 看状态 `s` → 网络直接吐出**唯一一条**动作块 `a = f(s)`，训练目标是让 `a` 尽量贴近专家动作（MSE 损失）。

### 2.2 痛点：同一个状态，专家可能做出**两个完全相反**的正确动作

Task 2 的场景里，专家控制器被故意改成**多峰**的（`expert_controller_multimodal`）。
看它的三条规则（`src/datasets.py` 第 100–116 行）：

```python
if abs(theta) < 0.5:                                   # ① 接近倒立 → PD 平衡（没有歧义）
    tau = -12.0 * theta - 1.5 * theta_dot
elif abs(theta) > pi - 0.5 and abs(theta_dot) < 1.0:    # ② 停在下垂附近、几乎静止 →
    tau = +2.0 if mode == 0 else -2.0                   #    "往左甩"还是"往右甩"由 mode 掷骰子决定
else:                                                  # ③ 其余状态 → 能量塑形摆起
    tau = 2.5 * theta_dot * sign(e_target - e_total)
```

关键在于 ③ 的"能量塑形"律 `τ = 2.5·θ̇·sign(ΔE)`：它靠"顺着运动方向推"来给系统注入能量。
可是当摆**几乎停住**（`θ̇ ≈ 0`）时这条规律自己退化成了 `τ ≈ 0` —— 推不动。所以专家在规则 ②
里给一个"起步助推"：**固定 ±2.0 的力矩**，方向随机选。往左甩能摆起来，往右甩也能摆起来，
**两个都对**。

于是数据里就出现了这样一件事（这是本任务的核心）：

```
                     同一个（或几乎同一个）状态 s
                                 │
              ┌──────────────────┴──────────────────┐
       约 57% 的演示里专家推 −2.0            约 43% 的演示里专家推 +2.0
       （顺时针甩）                          （逆时针甩）
```

也就是**条件分布 `p(a | s)` 有两个峰（双峰 / bimodal）**。

### 2.3 为什么"直接回归"在这时必然出事

MSE 损失 `L = E[(a − f(s))²]` 对 `f(s)` 求最小，数学上的最优解是**条件均值**：

$$f^*(s) = \mathbb{E}[a \mid s]$$

- 状态没有歧义时（比如摆已经朝右转、角速度也在转），专家动作只有一种，均值就是那个动作 —— 没问题。
- 状态有歧义时，样本里一部分是 `+2.0`、一部分是 `−2.0`（本项目实测 43.2% / 56.8%），
  均值落在两峰之间的"无人区" —— **网络会努力输出一个"既不是左也不是右"的动作**。
  在玩具任务那种"两峰各占一半"的严格设定下，这个均值恰好是 `0`，而 0 力矩在物理上
  等于"什么都不做"，摆就永远卡在下垂位置附近。

写成图更直观（同一个状态下的动作样本）：

```
数据里真实的 p(a|s)（双峰）            回归模型学到的（单点 = 均值）
 次数                                   次数
  ███                            ███
  ███                            ███
   │                              │
 ──┴──────────────────────────────┴────→ 动作 τ      ──────────────────────█────→ 动作 τ
  −2.0            0            +2.0                    −2.0      0        +2.0
        （中间几乎没样本）                                   ↑ 恰好落在"最没用的位置"
```

> 这个现象在文献里常被叫做 **"取平均陷阱" / 均值塌陷**：
> 分布的**期望**落在一个**概率极低**的位置，物理意义完全错误。

> **两个必须诚实说明的细节**：
> ① 现实数据里这些"歧义状态"并非逐位完全相同 —— 角速度 `θ̇` 哪怕很小，**正负号**仍然
>    泄露了该往哪边推。所以实测中回归网络并没有完全塌成 0，它靠符号"猜"对了一侧
>    （命中率 62.5%，见 6.2）；
> ② 真正证明"回归在无法区分模态时必然输出两峰均值"的，是第 6.6 节那个
>    **状态里不含任何线索**的玩具任务：实测输出 0.0096 ≈ 0，命中率 0%。

### 2.4 所以任务目标就是

**换掉"输出唯一值"的回归器，改用能输出整个分布的生成模型**，并回答两个问题：

1. 它真的能表达多峰吗（每次规划在两个模态之间"抽签"）？
2. 在真实闭环控制里，这份能力值不值它付出的代价（推理慢、抖动）？

## 3. 原理：扩散模型到底在干什么

### 3.1 一句话直觉：从"一次算出来"改成"从噪声里擦出来"

| | 回归策略（Task 1） | 扩散策略（Task 2） |
| --- | --- | --- |
| 网络 | `f(s)` | `ε_θ(s, a^t, t)` |
| 网络输出 | 动作块本身 | **噪声**（"这块动作里混进去的杂质"） |
| 一次规划调用几次网络 | 1 次 | **N 次**（默认 16） |
| 结果 | 唯一确定的一个动作块 | 从 `N(0, I)` 开始采样出的**一个样本**；再采一次会得到不同但同样合理的样本 |

打个比方：回归是"一次成型的模具"，扩散是"先拿一块大理石（纯噪声），再雕 16 刀"。
每一刀都只做一件简单的事——判断"现在这块料里还有哪些不该在的地方"（预测噪声），
但 16 刀叠起来，就能削出复杂形状（多峰的分布）。

### 3.2 前向加噪：训练时人为"制造难题"

训练数据里只有干净的动作 `a⁰`。为了教会网络"噪声长什么样"，我们要人为构造"干净动作 + 已知噪声"
的配对样本。DDPM 定义了一条**加噪链**（`t` 越大越吵，`t = 0` 最干净）：

* `α_t = 1 − β_t`，其中 `β_t` 是"第 t 步往里面掺多少噪声"；默认 `T = 100` 步；
* `ᾱ_t = α_0 · α_1 · … · α_t`（连乘，读作 "alpha bar"）；
* 加噪公式（`DiffusionSchedule.q_sample`）：

$$a^t = \sqrt{\bar\alpha_t}\, a^0 + \sqrt{1-\bar\alpha_t}\,\varepsilon,\qquad \varepsilon\sim\mathcal N(0,I)$$

也就是说：动作被**按比例缩放**（`√ᾱ_t`）并**混入**相应强度的高斯噪声（`√(1−ᾱ_t)·ε`）。

**β 怎么选？** 代码里默认用 **cosine（余弦）调度**——`ᾱ_t` 沿余弦曲线平滑衰减，比线性调度
"更晚地破坏结构信息、更快地在末端接近纯噪声"。本项目 `T = 100` 的实测数值：

| 扩散步 t | 0 | 10 | 25 | 50 | 75 | 90 | 99 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| `ᾱ_t`（信号保留比例） | 0.9994 | 0.9667 | 0.8356 | 0.4783 | 0.1335 | 0.0195 | ≈0（<1e-6） |
| `√ᾱ_t`（动作缩放） | 0.9997 | 0.9832 | 0.9141 | 0.6916 | 0.3654 | 0.1398 | 0.0005 |
| `√(1−ᾱ_t)`（噪声强度） | 0.0251 | 0.1824 | 0.4054 | 0.7223 | 0.9309 | 0.9902 | 1.0000 |

* `t = 0`：几乎还是原动作（噪声强度只有 0.025）；
* `t = 50`：信号与噪声大致各占一半（`ᾱ ≈ 0.48`）；
* `t = 99`：动作信息被彻底淹没（`ᾱ ≈ 2.5×10⁻⁷`），基本就是纯噪声。

### 3.3 关键技巧：不用真的迭代 100 次

把上面的链式递推展开，可以得到**一步跳到任意 t** 的闭式解：

$$q(a^t \mid a^0) = \mathcal N\!\left(\sqrt{\bar\alpha_t}\,a^0,\ (1-\bar\alpha_t)I\right)$$

所以**训练时随机抽一个时刻 `t`，一次乘法就造出 `a^t`**（代码里就是 `q_sample`）。
每个训练样本只多花"一个随机整数 t + 一个高斯噪声 ε"的成本，这也是扩散训练速度
和普通回归训练差不多的原因（实测 200 epoch 只要 5.5 分钟）。

### 3.4 网络要学的目标：预测"我刚刚加进去的那个噪声"

训练的损失极其简单（`DiffusionPolicy.p_losses`）：

$$\mathcal L = \mathbb E_{t \sim \mathcal U\{0,\dots,T-1\},\ \varepsilon \sim \mathcal N(0,I)}
\Big[ \big\| \varepsilon - \varepsilon_\theta(s,\ a^t,\ t) \big\|^2 \Big]$$

逐字读一遍：**随机挑一个时刻 t → 随机挑一份噪声 ε 加进干净动作 → 让网络看着
"状态 s、被弄脏的动作 a^t、时刻 t"，猜出刚才那份 ε"。** 猜错就罚。

注意这里没有任何"标签动作"参与损失——**标签是网络自己该去掉的那份噪声**。
`t` 是网络必须知道的输入（不同时刻"该去掉多少噪声"完全不同），所以状态 `s` 和时刻 `t`
是**两个条件**，这就是"条件扩散"（conditional diffusion）里"条件"两个字的来历。

> 代码里还做了一个小处理：动作块末尾的零填充（轨迹不够 K=8 步的地方）不参与损失
> （`valid` 掩码），否则网络会被教着"预测位置的噪声"。全数据里零填充只占 1.75%。

（下一节继续讲：为什么"预测噪声"就等于"学会分布"、反向采样怎么做。）

### 3.5 为什么"预测噪声"就等于"学会整个分布"

这是整个方法最需要理解的一步。核心是一个恒等式：给定"脏动作 `a^t`"和时刻 `t`，
**真实条件分布的梯度（score）与噪声是一一对应的**：

$$\nabla_{a^t} \log q(a^t \mid s) \;=\; -\,\frac{\varepsilon}{\sqrt{1-\bar\alpha_t}}$$

意思是：只要网络能准确预测"我加进去的噪声 ε"，它就等价于知道了
"往哪个方向挪一点点才能更像真实数据"（也就是分布的**对数密度的梯度**）。
而"知道往哪个方向挪"这件事，正是从噪声一步步走回动作所需要的全部信息。

于是两种训练目标的差别就清楚了：

| | 回归 + MSE（Task 1） | 扩散 + 噪声预测（Task 2） |
| --- | --- | --- |
| 学到的量 | 条件**均值** `E[a\|s]`（一阶矩） | 条件分布的对数密度**梯度**（整个形状） |
| 损失最优解 | 唯一的那个点 | 与真实 `p(a\|s)` 一致的采样分布 |
| 遇到双峰 | 只能给两峰中间的 `≈0` | 两个峰都被保留，"抽签"落到任一侧 |
| 代价 | 便宜（1 次前向） | 贵（每次生成要迭代 N 次） |

> **一个必要的心智转变**：因为网络学的是"往哪挪一点"而不是"最终答案在哪"，
> 生成动作就**必须一步一步来**（每步只挪一小段、还要按 `√ᾱ_t` 的节奏缩放）。
> 这就是"扩散策略推理慢"的根本原因——不是因为网络大，而是因为要跑 N 次。

### 3.6 反向采样：怎么从纯噪声走回动作（DDPM / DDIM）

有两种常用走法，代码里都实现了，默认用第二种。

**① DDPM（随机式，需要 T 步）**，每一步：

$$a^{t-1} = \underbrace{\mu_\theta(a^t, \hat a^0)}_{\text{后验均值（闭式）}} + \sigma_t z,\qquad
\hat a^0 = \frac{a^t - \sqrt{1-\bar\alpha_t}\,\varepsilon_\theta(s,a^t,t)}{\sqrt{\bar\alpha_t}},\quad z\sim\mathcal N(0,I)$$

第一项是"往正确方向挪一小步"，第二项是刻意留下的随机性。
其中 `â⁰` 就是"网络猜测的干净动作"，公式叫 **x0 预测**（`predict_x0_from_noise`），
代码里还把它截断到 `[−1, 1]`（归一化动作的合法范围）以避免个别步的极端外推。

**② DDIM（确定性式，可跨步）**，代码默认：

$$a^{t-1} = \sqrt{\bar\alpha_{t-1}}\,\hat a^0 + \sqrt{1-\bar\alpha_{t-1}-\sigma^2}\;\varepsilon_\theta
\;+\;\sigma z,\qquad \sigma = \eta\sqrt{\frac{1-\bar\alpha_{t-1}}{1-\bar\alpha_t}}\sqrt{1-\frac{\bar\alpha_t}{\bar\alpha_{t-1}}}$$

* `η = 0`（本项目默认）时 `σ = 0`：**给定起点噪声，去噪路径完全确定**；
* 因为公式里只用 `ᾱ_{t-1}` 而**不要求 t−1 与 t 相邻**，所以可以"跨步走"——
  把 100 步压成 **N = 16 步**，这是扩散策略能在控制回路里勉强可用的关键。

| | DDPM | DDIM |
| --- | --- | --- |
| 步数 | 必须 `T` 步（本项目 T=100 → 100 次前向） | 可任意 N 步（默认 16 次前向） |
| 随机性 | 每步注噪（同一次规划内也随机） | `η=0` 时无（只有起点噪声在随机） |
| 本项目用途 | 兼容选项（`diffusion.sampler=ddpm`） | **默认**采样器 |

> 常见误解："DDIM 是确定性的，那策略岂不是又变回确定性的了？"
> 不是。**确定性指的是"给定起点噪声，去噪过程唯一"**；而起点噪声 `a^N ~ N(0, I)`
> 每次规划都会重新抽，所以同一个状态下每次规划仍然得到**同一分布的不同样本** ——
> 多峰正是这样体现出来的。

### 3.7 多峰到底是怎么"冒出来"的

* **训练**时每个样本的 `t` 和 `ε` 都是独立随机的，所以网络见过"同一个状态 + 各种噪声"
  的组合，学到的是**所有可能去噪方向的总和**（即整个分布），而不是某一个答案；
* **采样**时从不同起点出发，去噪路径会流向不同的峰。用一个"状态完全看不出该选哪边"的
  玩具任务验证（详见第 6 节）：数据是 `a ~ N(±μ(s), 0.05²)`，`μ(s) = 1 + 0.5s`。
  扩散策略在每个状态采 512 次，得到的两侧命中比例是 **44.6% / 53.9%**（近似对半），
  并且逐状态的 `|a|` 均值 `[0.494, 0.730, 0.992, 1.251, 1.511]`
  与理论值 `|μ(s)| = [0.5, 0.75, 1.0, 1.25, 1.5]` **逐点吻合** ——
  它学到的是分布本身，而不是"另一个点估计"。

至此原理部分讲完。下一节看这套原理在代码里长什么样。

### 4.1 噪声网络长什么样（`ε_θ(s, a^t, t)`）

```
输入：
   状态 s        (B, 3)                 ← Pendulum 的 [cosθ, sinθ, θ̇]
   脏动作 a^t    (B, 8, 1)              ← 动作块 K=8
   扩散步 t      (B,)                   ← 0..99 的整数
        │
        ├── t  → SinusoidalTimeEmbedding → (B, 64)     ← 把"第几步"变成 64 维正弦波指纹
        ├── s  → Linear → GELU → (B, 128)
        │
        └── 拼成条件向量 c = [状态(128) ⊕ 时间(64)]
                 │
   a^t → Linear(8 → 128) → h (B, 128)
                 │
       ┌─────────┴────────────────────────────────────────────┐
       │  FiLM 残差块 × 3：                                     │
       │     h ← h + MLP( (1+γ(c)) ⊙ LayerNorm(h) + β(c) )      │
       └─────────┬────────────────────────────────────────────┘
                 │
            Linear(128 → 8) → reshape → 预测噪声 ε̂ (B, 8, 1)   ← 形状和 a^t 完全相同
```

三个设计点，各解决一个问题：

1. **时间步用正弦编码，而不是直接喂 `t/100`**：扩散步是"离散的全局刻度"，
   直接喂一个标量网络很难分辨相邻步；正弦编码把它展开成多频三角函数，网络更容易逼近
   "关于 t 的平滑函数"。
2. **状态与时间走 FiLM（Feature-wise Linear Modulation，也叫 AdaLN）调制**：
   每个残差块里，条件向量 `c` 只生成两组向量 `γ`、`β` 去**缩放和偏移**中间特征，
   也就是"在什么状态、什么噪声水平下，该重点看哪些特征"。这比"把条件拼到输入"更省参数、
   也更好训（扩散策略 / DiT 等主流做法）。
3. **输出形状 = 输入动作块形状**：网络是逐点预测噪声的，因此**天然支持动作块**
   （一次预测 K=8 步），这也是它和 Task 1 动作块 BC 能直接对比的原因。

规模对比：噪声网络 **358,152** 个可训练参数，Task 1 的回归头只有 **18,056** 个
（差 19.8 倍）——这是"多峰能力"的另一部分代价。

### 4.2 与旧策略接口完全一致（工程上的关键一点）

`DiffusionPolicy` 对外只暴露 `forward(state)` / `forward_actions(state)`，
返回的也是 `(B, K, action_dim)` 的动作块（已乘回力矩上限并截断）。因此：

* `src/datasets.py` 里的闭环 rollout 代码 **一行都不用改**；
* `src/engine.py` 的训练循环也**一行都不用改**（噪声预测损失通过 `step_fn` 注入）；
* 两种策略在同一套评估协议下对比，**比较的确实是"动作生成方式"，而不是"评估脚本的差异"**。

## 5. 我具体做了什么：训练与推理的完整流程

### 5.1 训练一步（伪代码，对应 `DiffusionPolicy.p_losses`）

```python
for (s, a_chunk, valid) in train_loader:      # s: (B,3)  a_chunk: (B,8,1)  valid: (B,8)
    a0 = a_chunk / 2.0                        # ① 归一化：力矩 [-2,2] → [-1,1]
    t  = randint(0, 100, size=B)              # ② 每个样本抽一个随机扩散步
    eps = randn_like(a0)                      # ③ 每个样本抽一份随机噪声
    a_t = sqrt(acp[t]) * a0 + sqrt(1 - acp[t]) * eps     # ④ 一步加噪（q_sample）
    eps_hat = noise_net(s, a_t, t)            # ⑤ 噪声网络前向（1 次）
    loss = ((eps_hat - eps) ** 2 * valid).mean()         # ⑥ 只惩罚"没猜对噪声"（掩掉零填充）
    loss.backward(); optimizer.step()
```

**关键：训练阶段没有"去噪循环"**。每次只用 1 次前向，随机挑一个噪声水平去练，
所以训练成本和普通回归几乎一样（200 epoch 实测 333 秒）。

### 5.2 推理一次规划（伪代码，对应 `DiffusionPolicy.sample`）

```python
@torch.no_grad()
def 规划一条动作块(s):
    a = randn(8, 1)                                   # ① 起点：纯高斯噪声（★ 每次规划都重新抽）
    for t in [99, 93, ..., 6, 0]:                     # ② 16 个跨步子步（DDIM，N=16）
        eps_hat = noise_net(s, a, t)                  # ③ 网络前向（第 N 次）
        a0_hat  = clamp((a - sqrt(1-acp[t]) * eps_hat) / sqrt(acp[t]), -1, 1)   # ④ x0 预测
        a = sqrt(acp_prev) * a0_hat + sqrt(1 - acp_prev) * eps_hat             # ⑤ DDIM 走一步（η=0）
    return clamp(a * 2.0, -2, 2)                      # ⑥ 反归一化 + 截断 → 交给环境执行 8 步
```

* ① 就是"多峰"的来源：**同一个状态、不同的起点噪声 → 不同的模态**；
* ② 是本项目默认配置（`T=100` 训练 / `N=16` 推理）：一步规划 = **16 次网络前向**，
  而回归策略只要 1 次 —— 这就是"慢 132.8 倍"的直接原因；
* ⑤ 里 `η=0`，所以给定起点后整条路径是确定的（这也是 `tests/test_diffusion.py` 能逐位校验的原因）。

## 6. 结果（全部为实测数字，来自 `logs/diffusion_policy_pendulum_20260916_181837/diffusion_report.json`）

### 6.1 闭环回报：扩散没有赢

配置：两个策略用**同一份多峰数据、同样的 200 epoch、同样的动作块 K=8、同样的 20 个回合**；
扩散用 `T=100`（cosine 调度）+ `N=16` 步 DDIM（`η=0`），每 8 步规划一次。

| 指标 | 确定性 MLP（回归均值） | 扩散策略（分布采样） | 差异 |
| --- | --- | --- | --- |
| 闭环平均回报 | **−181.72 ± 85.99** | −331.83 ± 173.47 | Δ = −150.1（池化 std 129.7） |
| 失败回合（回报 < −800） | 0 / 20 | 0 / 20 | 两者都能把摆摆起来 |
| 每回合网络前向次数 | **25** | 400（25 次规划 × 16 步） | 16× |
| 单次规划耗时 | **0.186 ms**（5373 次/秒） | 24.72 ms（40 次/秒） | **慢 132.8 倍** |
| 可训练参数量 | 18,056 | 358,152 | 19.8× |
| 验证集指标 | 动作块 MSE 0.2510（best） | 噪声 MSE 0.0386（best）/ 0.0367（末轮）；动作块重建 MSE 0.0993 | — |

**怎么读这张表**：两者的差距**不是**"扩散摆不起来"（失败回合都是 0），而是**摆起效率**——
扩散每次方向"抽签"抽得摇摆一些，摆起来要来回更多次，扣分更多。

### 6.2 多峰探针：扩散确实在"输出分布"

在 8 个**训练时没见过**的歧义状态上（用 seed 10000+ 独立生成），每个状态采样 256 次：

| 指标 | 确定性 MLP | 扩散策略 |
| --- | --- | --- |
| 同一状态采样标准差 | **0.000**（永远输出同一个动作） | 1.124 |
| 命中"任一模态"的比例 | 62.5% | **71.7%** |
| 到最近模态的平均距离 | 0.518 | **0.311** |
| 两侧模态都被采到的状态比例 | 0% | 62.5% |

结论：扩散**真的在采样一个分布**（有方差、有 62.5% 的状态两侧都采到），而且在新状态上
命中率比回归高 9.2 个百分点。回归也没像我一开始担心的那样"塌成 0"——它靠相邻状态的
角速度符号"猜"对了一侧（62.5%），这也是它最终赢下闭环的原因。

### 6.3 采样步数 N 与重规划频率：甜点在 10~16 步

| 变体 | 闭环回报 | 每回合前向 | 相对算力 |
| --- | --- | --- | --- |
| `N = 4` | −494.75 ± 301.41 | 100 | 0.25× |
| `N = 10` | −325.53 ± 222.48 | 250 | 0.63× |
| `N = 16`（默认） | **−315.16 ± 214.74** | 400 | 1× |
| `N = 32` | −428.72 ± 231.19 | 800 | 2× |
| `N = 16` + 每 4 步重规划 | −318.00 ± 221.48 | 800 | 1×（规划次数 ×2） |

* `N = 4` 明显不行（−494.8）：跨度太粗，去噪没走够，动作块偏离数据分布；
* `N = 10 / 16 / 32` 之间的差异都在回合间标准差（214~231）范围内，**不能据此宣称谁更好**，
  但 `N = 32` 花两倍算力没有回报 → 默认取 `N = 16` 是合理的工程选择；
* 把重规划间隔从 8 步缩到 4 步（规划次数翻倍）几乎没变化（−318.0 vs −315.2），
  说明**瓶颈不是"规划不够勤"，而是"每次规划都独立抽签"**；
* 顺带一个诚实提醒：同一配置在 6.1（−331.83）和本表（−315.16）里差了 16.7，
  即 20 回合评估的**复现噪声约 ±17** —— 小于两个策略之间的差距，所以 6.1 的结论成立。

### 6.4 规划一致性：多峰采样的"抖动"有多大

统计 10 个回合里、相邻两次规划之间"动作块第一个动作的符号是否翻转"（每回合 25 次规划）：

| 策略 | 每回合翻转次数 | 翻转率 |
| --- | --- | --- |
| 确定性 MLP | 17.5 / 25 | 70.0% |
| 扩散策略 | **12.3 / 25** | 49.2% |

结论有点反直觉：**扩散反而更"稳定"**。原因是回归策略在歧义边界附近"决策面很陡"，
状态微微变化就会改主意；扩散一旦抽到某一侧，在接下来几次规划里更倾向留在那一侧。
所以"多峰 ⇒ 抖动"的说法在本任务里**不成立**，扩散的问题主要是"抽签结果本身可能选错方向"。

### 6.5 稀疏数据消融：结果和我的预期**相反**（如实记录）

我原本的假设是：**数据越少，回归越难"记住"每条演示该往哪边，越容易掉进均值陷阱，扩散应当反超。**
于是只用 **16% 的轨迹**（8/50 条、1600 步、1280 个训练样本），两种策略各训 120 epoch：

| 策略 | 闭环回报 | 探针命中率 | 探针平均 \|a\| | 训练指标 |
| --- | --- | --- | --- | --- |
| 确定性 MLP | **−203.95 ± 100.23** | **50.0%** | 1.642 | 动作块 MSE 0.3369（全量时 0.2510） |
| 扩散策略 | −882.73 ± 111.49 | 5.2% | 0.753 | 噪声 MSE 0.0758（全量时 0.0386） |

**假设不成立，而且差距很大。** 原因有两条，都可以从数字里看出来：

1. **数据少时扩散是"欠拟合 + 分布变钝"**：噪声预测误差从 0.0386 涨到 0.0758（涨 96%），
   采样出来的动作幅值从 1.689 掉到 0.753 —— 也就是**它开始向均值塌缩了**，
   命中率从 71.7% 崩到 5.2%。扩散需要先把"两个峰"学 sharp 才能派上用场，**数据不足时它更早失效**。
2. **倒立摆的歧义是"瞬时且可以绕开"的**：歧义状态只占 0.95%，且都是"几乎停住"的短暂瞬间；
   回归器即使没见过这些精确状态，也能用相邻状态（角度、角速度符号）外推到一侧。

一句话：**"多峰 ⇒ 扩散更好"只在"状态真的无法区分模态、且歧义决定成败"时才成立** ——
也就是下面那个玩具任务。

### 6.6 双峰玩具任务：最干净、最有力的证据

数据完全可控：1 维状态 `s`，动作 `a ~ N(±μ(s), 0.05²)`，`μ(s) = 1 + 0.5s`。
也就是"动作有两个模态，选哪个对策略来说**完全不可观测**"，测试 5 个状态、每状态采 512 次：

| 指标 | 确定性 MLP（MSE） | 扩散策略 |
| --- | --- | --- |
| 平均 \|a\| | 0.0096 ≈ **0** | 0.995 |
| 到最近模态的距离 | 0.990 | **0.047** |
| 命中率（落在某个模态附近） | **0%** | **98.5%**（负峰 44.6% / 正峰 53.9%） |
| 两个模态都被采到 | 0% | **100%** |
| 逐状态 \|a\| 均值 | ≈0, ≈0, ≈0, ≈0, ≈0 | 0.494 / 0.730 / **0.992** / 1.251 / 1.511 |
| 理论值 \|μ(s)\| | 0.5 / 0.75 / 1.0 / 1.25 / 1.5 | 0.5 / 0.75 / 1.0 / 1.25 / 1.5 |

这就是 2.3 节那张示意图的实测版：**回归严格收敛到两峰中间的 0（命中率 0%），
扩散把两个峰都完整保留下来（命中率 98.5%、两侧各约一半、幅值与理论值逐点吻合）**。

**这是 Task 2 最核心的科学结论**：扩散策略学到的确实是条件分布 `p(a|s)`，
而不只是"另一个点估计"；而它的代价与收益，取决于任务里"看不出该选哪个"这件事
到底有多重要。

## 7. 结论：这次工作到底得出了什么

### 7.1 三句话

1. **能力上，扩散赢了**：在"状态无法区分模态"的设定下，回归的输出严格是两峰均值
   （实测 = 0.0096，命中率 0%），扩散保留了完整的双峰（命中率 98.5%、两侧各半、
   幅值与解析值逐点吻合）。在倒立摆**没见过**的歧义状态上，命中率也从 62.5% 提到 71.7%。
2. **分数上，扩散输了**：闭环回报 −331.8 vs −181.7；单次规划慢 **132.8 倍**（24.72 ms）。
   原因是倒立摆里"歧义瞬间"只占 0.95% 的状态，其余状态足以让回归判断方向；
   而扩散每次重新抽签，抽到不利方向的代价比"取平均"更大。
3. **数据上，扩散更吃亏**：只用 16% 数据时是 −882.7 vs −204.0。扩散必须先"把峰学 sharp"，
   数据不足时它的采样分布会变钝（噪声误差 +96%、采样幅值 1.69 → 0.75），比回归更早失效。

### 7.2 决策清单：什么时候值得为"分布"付这笔钱

| 你的任务长这样 | 建议 |
| --- | --- |
| 同一状态有多个**都正确**的动作，而且选错方向代价很大（多解抓取、左右绕障、双臂协同） | **上扩散**（或至少用 CVAE / 多模态头） |
| 歧义只是**短暂瞬间**，且邻近状态能提供足够信息（本项目的倒立摆） | **用回归更划算**（分数更高、快 130 倍） |
| 数据很少（< 20% 的目标规模） | **先别上扩散**，它比回归更早失效；先补数据 |
| 推理预算很紧（控制周期 < 10 ms） | 用 `N = 10` 甚至更少；或等一步生成模型（一致性模型 / 蒸馏） |

### 7.3 如果继续往下做，可以改进的地方

1. **压住"抽签抖动"**：把起点噪声按回合固定（`diffusion.seed`），或对同一状态采样 M 次后
   取"最一致/最接近数据流形"的样本（一致性引导采样）。
2. **换更快的采样器**：一致性模型 / 蒸馏 DDIM 可以 1~4 步生成，直接把 132.8 倍压到 10 倍以内。
3. **在真正多解的任务上验证**：本项目用的是"人为制造多峰"的 Pendulum；
   下一步应该走到真实的"多解抓取/绕障"任务（W10 之后的 Isaac Lab / 真机）。
4. **加大模型与数据**：本次是 358k 参数、10000 步数据的**最小**验证；扩散的分布建模能力
   通常随规模继续增长（回归的"均值塌陷"不会因为变大而消失，但会变得更"细分"）。

### 9.1 术语表（按出现顺序）

| 术语 | 英文 | 一句话解释 |
| --- | --- | --- |
| 模仿学习 | imitation learning | 从专家示范里学策略，而不是让机器人自己试错 |
| 行为克隆 | behavior cloning (BC) | 把 `(状态, 专家动作)` 当监督样本，用回归/分类去模仿 |
| 动作块 | action chunk | 一次预测未来 K 步动作，减少推理次数 |
| 条件分布 | conditional distribution `p(a\|s)` | 同一状态下动作的分布；"多峰"就指它有多个峰 |

| 去噪步数 | sampling steps (`N`) | 本项目 `N=16`（DDIM 跨步）；N 越小越快越粗 |
| DDPM | Denoising Diffusion Probabilistic Models | 原始随机采样器，需要 T 步 |
| DDIM | Denoising Diffusion Implicit Models | 确定性采样器，可跨步到 N 步；本项目默认 |
| x0 预测 | x0-prediction | 由"脏动作 − 预测噪声"反推出干净动作，再去噪一步 |
| score | score function `∇ log p` | 分布对数密度的梯度；预测噪声等价于学它 |
| FiLM / AdaLN | Feature-wise Linear Modulation | 用条件向量去缩放/偏移特征，实现"条件化" |

| 一致性采样 | consistency sampling | 多次采样后取"彼此最一致"的样本，抑制抽签抖动 |

## 10. 常见问题（FAQ）

**Q1：为什么训练只要 1 次网络前向，推理却要 N 次？**
因为训练和推理在做**两件不同的事**。训练是"给一堆已知的脏动作打分"——网络只需看一个随机时刻的
脏动作，猜它被掺了什么噪声（1 次前向就够）。推理是"从零开始生成"——没人告诉我们动作在哪，
只能从纯噪声出发，每次只挪一小步（因为网络只学会"往哪挪一点"，没学会"一步到位"），
所以要走 N 次。这也是所有扩散模型的共同特征。

**Q2：扩散策略的"随机性"来自哪里？**
两个地方，本项目只用了第一个：① **起点噪声** `a^N ~ N(0, I)` 每次规划重新抽（主要来源，
也是多峰的直接体现）；② DDIM 的 `η > 0` 时每步也注噪（本项目 `η = 0`）。
注意：`η = 0` 不代表"策略变确定"，因为每次规划的起点噪声都不一样。

**Q3：为什么不直接让网络预测干净动作 `â⁰`，而要绕一圈预测噪声？**
可以（这叫 x0 参数化，DDPM 后续文献里很常见），但纯粹预测 `â⁰` 时，
在高噪声时刻（`t` 大）输入几乎是纯噪声、目标却是一个具体动作，任务太难、梯度尺度在各时刻
差异很大。预测噪声的好处是：**不同 t 的预测目标尺度统一**（都是标准高斯），训练更稳。
本项目采用"预测噪声"，但在去噪每一步都会立刻把它换算成 `â⁰`（`predict_x0_from_noise`），
所以两种视角都保留着。

**Q4：验证集的"噪声 MSE = 0.0386"算好还是坏？**
噪声本身是标准高斯（方差 1），如果网络什么都不学，MSE ≈ 1。0.0386 表示网络对噪声的解释力
已经相当强。但**它不是最终指标**：噪声 MSE 好只说明"分布学得像"，能不能控制好还要看闭环回报
（这也是本项目坚持报闭环回报 + 探针 + 延迟三件套的原因）。

**Q5：回归在没见过的歧义状态上，为什么没有塌成 0？**
因为在真实的倒立摆里，"完全无法区分"的状态极少：歧义状态只占 0.95%，而且这些状态的**邻域**
里角速度符号是明确的信息，回归网络会利用邻域信息"猜"一侧（实测命中率 62.5%）。
只有像玩具任务那样"状态里完全没有任何线索"时，回归才必然输出 0。

**Q6：那 Task 2 算是"失败"吗？**
不是。它给出了一个有边界的结论：**扩散的收益是"分布表达"，代价是"采样成本 + 数据需求"**；
在倒立摆上这笔交易不划算，但在"多解"真正决定成败的任务上是必须的。同时它还交付了可复用的
最小实现（358k 参数、5.5 分钟训练、15 个单测、接口与旧策略一致）。**"量化出什么时候不用它"
本身就是一个有价值的工程结论**——否则很容易盲目地把扩散塞进所有任务里。

**Q7：这套代码能直接搬到机械臂吗？**
网络结构基本可以直接用（`state_dim` / `action_dim` / `chunk_size` 都是配置项），
需要换的是：① 数据来源（真实/仿真机械臂的状态与动作，维度更高）；② 归一化方式
（现在动作假设在 `[-action_scale, action_scale]`）；③ 推理预算（把 N 压到 10 以内，
或换一步生成模型）。这也是后续 W6-W12 的路线。
